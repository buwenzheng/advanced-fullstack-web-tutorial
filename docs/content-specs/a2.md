## 1. 出口能力

1. 解释哈希函数、冲突、负载因子与扩容的关系。
2. 实现开放寻址哈希表，并处理删除墓碑与 rehash。
3. 识别哈希洪水、最坏 O(n)、迭代顺序不稳定等边界。
4. 判断什么时候不该用哈希表（范围查询、排序、内存敏感）。

## 2. 起点与误解

- 已经知道：哈希表用于 O(1) 查找、Redis 使用哈希结构。
- 常见误解：
  - 「哈希表永远 O(1)」——冲突与扩容会带来最坏 O(n)。
  - 「删除直接把槽位置空」——探测链会断裂。
  - 「哈希表能保序」——迭代顺序不稳定，不能当排序结构。

## 3. 范围边界

- 本讲只讲：哈希函数、冲突处理、墓碑、扩容、负载因子与适用边界。
- 不讲：Redis 缓存策略与淘汰（`s3-l1`）、B+tree/LSM（a3）、并发哈希表实现。
- 与相邻讲分工：a2 讲哈希表本身，a3 讲有序索引结构。

## 6. 练习

- 代码题：`createHashMap({ initialCapacity = 8, maxLoad = 0.75 })`。
- 方法：`set/get/has/delete/size/loadFactor`；字符串 key；线性探测；墓碑；超过负载因子扩容 2 倍并 rehash。
- 负载因子口径：`(size + tombstones) / capacity`。
- 测试 ≥9：基本读写、覆盖、冲突、删除、墓碑复用、扩容、负载因子、大量 key、缺失 key。
- Python：类 + list，墓碑用哨兵；测试逐条对齐。

## 7. 事实与夹具

- 事实：不同语言哈希表实现不同；哈希函数质量影响最坏情况；迭代顺序不保证稳定。
- 不新增夹具。
