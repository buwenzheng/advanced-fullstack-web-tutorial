## 1. 出口能力

1. 设计可复现的压测基线：负载模型、并发、时长、数据量与环境。
2. 正确解读吞吐、P50/P95/P99、错误率与饱和度。
3. 用 profile、火焰图与慢查询定位 CPU/IO/锁/下游瓶颈。
4. 用 Little 定律做容量估算，并写清假设。

## 2. 学习者起点与常见误解

- 已经知道：Lighthouse 分数、浏览器 Performance 面板、接口耗时。
- 常见误解：
  - 「平均延迟低就快。」——平均值掩盖尾延迟与长尾用户。
  - 「并发数等于 QPS。」——并发是在途请求数，QPS 是到达率，靠 Little 定律关联。
  - 「压测一次就够。」——冷缓存、数据量与部署差异会让结论失效。
  - 「CPU 不高就没有瓶颈。」——IO 等待、锁竞争、连接池与下游慢都可能让 CPU 空闲。
  - 「压测工具的数字是绝对值。」——开环/闭环模型不同，结果依赖环境。

## 3. 范围边界

- 本讲只讲：压测设计、指标解读、profile 定位、Little 定律容量估算。
- 本讲不讲：排队论的完整数学推导（b-capacity）、Linux IO 内核与反向代理细节（b-linux）、具体压测产品教程。
- 与相邻讲的分工：m3-otel 提供指标口径；本讲用指标找瓶颈；b-capacity 深入容量建模。

## 6. 代码题：压测结果汇总

契约：`summarizeLoadTest(samples, { durationSec })`，`samples` 为 `{ latencyMs, ok }`。

- 返回 `{ count, throughput, errorRate, p50, p95, p99, avgConcurrency }`。
- `count` 为全部样本数；`throughput = count / durationSec`（每秒请求数）。
- `errorRate = 失败数 / count`；空样本全为 0。
- 延迟分位只统计成功样本，用最近秩；无成功样本时为 0。
- `avgConcurrency = (成功数 / durationSec) × (成功样本平均延迟 ms / 1000)`，即 Little 定律。
- 参数非法（durationSec ≤ 0）抛 RangeError。

测试（≥6）：空样本；全成功分位；含错误时错误率与分位排除错误；分位边界；吞吐计算；并发估算；非法时长。

Python 差异：排序、`math.ceil`、dict 返回；除零保护与 JS 一致。

## 7. 方案题：LinkHub 容量估算

自检清单（≥6）：峰值 QPS；读写比；缓存命中；单实例容量；冗余；增长；成本；压测验证；瓶颈假设。

参考要点：先基线后容量；区分平均与峰值；2-3 倍冗余；假设可证伪；用压测验证。
