## 1. 出口能力

1. 在 SSE/WebSocket/长轮询之间按方向、基础设施与成本做选择。
2. 设计重连、退避、去重、断点续传与降级轮询。
3. 用 HttpOnly/SameSite/CSRF/CSP 组合建立浏览器会话的安全边界。
4. 识别 XSS/CORS/越权/租户隔离在全栈中的责任分界。

## 2. 学习者起点与常见误解

- 已经知道：Cookie/Session、CORS 预检、API 鉴权与角色模型、XSS 的基本概念。
- 常见误解：
  - 「实时就一定要 WebSocket。」——单向通知用 SSE 更简单，HTTP 代理兼容更好。
  - 「重连就是再连一次。」——没有退避与 jitter 会形成重连风暴。
  - 「Cookie 有 HttpOnly 就不需要 CSRF。」——浏览器会自动携带 Cookie，跨站请求仍成立。
  - 「CORS 配 `*` 加 credentials 也能用。」——规范禁止两者组合。
  - 「事件按内容去重就行。」——内容相同不代表同一事件，必须用稳定 id。

## 3. 范围边界

- 本讲只讲：实时传输选择、重连与事件归并、浏览器会话、CSRF/CSP/CORS、越权与租户隔离的责任边界。
- 本讲不讲：API 授权模型与角色设计（s2-l3）、OIDC 协议完整实现、WAF/风控产品。
- 与相邻讲的分工：s2-l3 讲「谁能调用这个 API」；本讲讲「浏览器如何安全地持有会话」与「实时链路如何不重复不丢」。

## 6. 代码题：重连计划 + 实时事件归并（跨层：传输 → UI 状态）

契约：

- `planReconnect(attempt, options)`：`{ baseMs = 100, maxMs = 1600, jitter = 0.2, maxAttempts = 5, random = Math.random }`。
  - `attempt` 从 0 开始；`attempt >= maxAttempts` 返回 `{ delayMs: 0, exhausted: true }`。
  - 否则 `raw = min(baseMs * 2^attempt, maxMs)`；`delayMs = round(raw * (1 - jitter + 2 * jitter * random()))`。
  - `random` 注入，测试可复现；`random = 0` 取下界，`random = 1` 取上界。
- `applyLiveEvent(state, event)`：`state = { total, perLink, seenIds, lastEventId, lastSeq }`。
  - 事件 `{ id, linkId, delta, seq }`；重复 `id` 忽略，不重复累加。
  - 新 id 累加 `total` 与 `perLink[linkId]`；乱序（seq 小于 `lastSeq`）仍只按 id 累加一次。
  - `seq > lastSeq + 1` 时返回状态带 `gap: true`；相邻 seq 不带。
  - `lastEventId` 在 seq 更大时更新；`seenIds` 去重；不修改入参。

测试（9）：退避序列；封顶；jitter 上下界；耗尽；重复事件只加一次；两个链接独立累加；乱序不重复；缺口标记；入参不可变。

Python 差异：`min(base * 2 ** attempt, max)`；`random.random()` 注入；dict 拷贝；测试用固定 random；异步测试。

## 7. 方案题：LinkHub 实时与安全设计

自检清单（13）：传输选择；鉴权方式；订阅粒度；扇出与背压；重连/补拉；去重；降级轮询；会话存储；CSRF；CSP；CORS；租户隔离；审计日志。

参考要点：实时链路必须能降级；会话 Cookie 必须 HttpOnly + SameSite + CSRF token；CORS 不允许 `*` 与 credentials 组合；事件去重放在 UI 状态层而不是只靠服务端。
