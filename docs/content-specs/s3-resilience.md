## 1. 出口能力

1. 设计分层超时与截止时间传播，避免下游超时晚于上游。
2. 实现带预算与抖动的重试，区分可重试错误，避免重试风暴。
3. 实现熔断器三态（closed/open/half-open）与隔离舱，说明阈值与冷却的取舍。
4. 实现幂等键语义，理解分布式锁的租约与 fencing token 边界。

## 2. 学习者起点与常见误解

- 已经知道：`fetch` 失败会重试；超时会中断请求；幂等键在 s2-l4 出现过；锁可以串行化写。
- 常见误解：
  - 「重试越多越可靠。」——每次重试都放大下游流量；错误类型不对时只是制造风暴。
  - 「所有 4xx 都可以重试。」——400/401/403/404/422 通常不可重试；429 与部分 5xx 才可能。
  - 「超时只设一个总时长。」——客户端、网关、服务、下游要分层，且要传递剩余截止时间。
  - 「熔断打开就永远拒绝。」——冷却后要半开探测；半开并发过多会再次打垮下游。
  - 「有分布式锁就不会并发写。」——锁会过期、时钟会漂移、旧持有者可能继续写；需要 fencing token 或版本号。
  - 「幂等键会自动去重。」——需要存储、作用域、TTL 与冲突语义；实现不在契约里自动出现。

## 3. 范围边界

- 本讲只讲：
  - 分层超时与 deadline；
  - 重试预算、退避、抖动与可重试判定；
  - 熔断器三态与隔离舱；
  - 幂等键实现与分布式锁边界；
  - LinkHub 的故障演练。
- 本讲不讲：
  - Outbox/Saga 与跨服务最终一致（s5-l2）；
  - 服务网格与产品化熔断配置；
  - 分布式共识与强一致协议（s5）；
  - 幂等键契约本身（s2-l4 已定义，本讲实现）。
- 与相邻讲的分工：s2-l4 定义幂等键契约；本讲实现存储、并发与锁边界；s5 处理跨服务一致性。

## 5. 概念检查（3 题）

### C1

- ID：`s3-resilience-check-1`
- 类型：单选
- 考点：哪些错误适合重试；POST 重试的前提
- 正确项：网络超时/连接失败与部分 5xx 可重试；非幂等 POST 必须先有幂等键
- 解析要点：4xx 参数错误重试无意义；429 按 Retry-After；重试要计预算。

### C2

- ID：`s3-resilience-check-2`
- 类型：多选
- 考点：熔断器状态与转换
- 正确项：连续失败达到阈值进入 open；冷却后 half-open；半开成功回 closed；半开失败回 open
- 解析要点：open 期间直接拒绝；半开只放有限探测；成功要重置计数。

### C3

- ID：`s3-resilience-check-3`
- 类型：单选
- 考点：同一幂等键不同 body
- 正确项：返回冲突（如 409），不能静默执行第二次
- 解析要点：同键同 body 返回首次结果；执行中重放要可查询；TTL 决定重放窗口。

## 6. 代码题：重试计划 + 熔断器

- 契约 A：`planRetries({ maxAttempts = 3, baseDelayMs = 100, maxDelayMs = 10000, budget = Infinity, random = Math.random } = {})`
  - 返回每次重试的延迟数组，长度为 `maxAttempts - 1`（预算不足时更短）；
  - 第 i 次基础延迟 `baseDelayMs * 2^i`，封顶 `maxDelayMs`；
  - 抖动系数在 `[0.5, 1.5]`，用注入的 `random()` 计算；
  - 若加入下一次延迟会超过 `budget`，停止并返回已累计的延迟。
- 契约 B：`createCircuitBreaker({ failureThreshold = 3, cooldownMs = 1000, now = Date.now } = {})`
  - `execute(fn)` 异步执行；closed 连续失败达到阈值 → open；
  - open 期间直接抛错；冷却时间到后进入 half-open；
  - half-open 只允许一个探测；成功 → closed 并清零，失败 → open 并重置冷却起点；
  - 需要可观察状态（`state` getter 或 `getState()`）。
- 测试（≥8）：
  1. 重试延迟指数递增；
  2. 抖动下界与上界；
  3. 最大延迟封顶；
  4. 预算耗尽停止；
  5. `maxAttempts = 1` 返回空数组；
  6. 连续失败达到阈值打开熔断；
  7. 冷却后半开探测成功回到 closed；
  8. 半开探测失败回到 open；
  9. 成功调用重置失败计数。
- 测试设计说明：`random` 注入固定值，避免概率测试；`now` 用 `clock` 变量推进；熔断测试用会抛错的函数并断言调用次数，确认 open 期间没有执行 `fn`。
- Python 差异：同步版本；`random.Random(seed)` 生成确定性序列；`now` 注入；熔断器用类与 `state` 属性；`execute` 用 `try/except`。
- 常见错误：重试所有 4xx；抖动没有上下界；熔断打开后仍放行；半开并发探测过多；成功不重置计数。

场景：跳转链路依赖统计服务；统计服务偶发超时；创建接口重复提交会产生多条短链；未来可能多实例部署。
