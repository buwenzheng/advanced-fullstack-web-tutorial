## 1. 出口能力

1. 从 OpenAPI 生成类型安全客户端，并解释生成物为什么不能手改。
2. 设计契约漂移检查，把破坏性变更挡在合并之前。
3. 判断何时需要 BFF、何时直连，并说清 BFF 的收益与代价。
4. 用并发聚合、总超时与部分失败降级消除前端请求瀑布。

## 2. 学习者起点与常见误解

- 已经知道：HTTP 请求/响应、REST 资源、状态码、OpenAPI 的基本形状。
- 常见误解：
  - 「前端类型手写一份就行。」——手写类型会与后端漂移，编译通过不代表契约一致。
  - 「生成物可以临时改一下。」——手改会在下次生成时被覆盖，且 CI 无法区分。
  - 「BFF 就是把四个请求转发一遍。」——BFF 的价值是聚合、裁剪与降级，不是多一跳。
  - 「用 `Promise.all` 就行。」——任一失败会整体失败，无法做部分降级。
  - 「超时给每个上游各配一个就够了。」——没有总预算时，串行等待会叠加。

## 3. 范围边界

- 本讲只讲：契约生成、漂移检查、BFF 取舍、并发聚合、总超时、部分失败与错误码映射。
- 本讲不讲：HTTP 报文与缓存基础（S0）、资源建模与契约设计（S2）、浏览器会话与 CSRF（s6-l3）。
- 与相邻讲的分工：S2 定义契约内容；本讲把契约变成生成物与运行时聚合；s6-l2 讲渲染，不重复聚合。

## 6. 代码题：类型客户端 + BFF 聚合（跨层：契约 → UI 数据）

契约：

- `buildClient(schema, { transport })`：`schema = { paths: { '/links/{id}': { get: { pathParams, query, response } } } }`。
  - `client.get(template, params = {})`：替换 `{name}` 并对参数做 `encodeURIComponent`；缺失路径参数抛 `MISSING_PARAM`。
  - 查询串只包含 `query` 声明且值不为 `undefined` 的字段，按字段名升序，键值都编码。
  - 未知模板抛 `UNKNOWN_ROUTE`，错误对象带 `code`。
  - 调用注入的 `transport({ method: 'GET', path, query })`；`response.required` 中的字段缺失时抛 `INVALID_RESPONSE`。
- `createDetailLoader({ fetchMeta, fetchStats, fetchPermission, timeoutMs, scheduler })`：返回 `loadDetail(id)`。
  - 三个上游在同一轮同步启动，不得顺序 `await`。
  - `meta` 失败整体失败：错误 `code === 'NOT_FOUND'` 映射 `{ code: 'NOT_FOUND' }`，其余含超时映射 `{ code: 'UPSTREAM' }`，不透传原始错误。
  - `stats` 失败 → `stats: null`，`degraded` 含 `'stats'`；`permission` 失败 → `canEdit: false`，`degraded` 含 `'permission'`。
  - 成功形状 `{ link, stats, canEdit, degraded }`；`degraded` 顺序固定为 stats → permission。
  - `timeoutMs` 是整次聚合总预算；超时后已完成的字段保留，仍 pending 的 stats/permission 记入 `degraded`；meta 未完成返回 `{ code: 'UPSTREAM' }`；超时后到达的结果必须忽略。
  - 测试注入假 `scheduler = { setTimeout, clearTimeout }` 手动推进，不依赖真实计时器。

测试（9）：路径/查询编码与排序；未知路径；缺失路径参数；响应必填校验；三上游并发启动；全成功无降级；stats 失败只降级 stats；meta 失败映射 NOT_FOUND/UPSTREAM；总超时保留已完成字段并忽略迟到结果；meta 未完成超时返回 UPSTREAM。

Python 差异：`urllib.parse.quote` 编码；`asyncio.gather(..., return_exceptions=True)` 并发；`asyncio.wait_for` 实现总超时；返回 dict；测试用 `asyncio` 与短超时。

## 7. 方案题：LinkHub 详情页 BFF 契约

自检清单（9）：输入/输出 schema；聚合的上游；并发与超时预算；部分失败策略；鉴权透传；错误码映射；缓存边界；类型同步方式；可观测字段。

参考要点：BFF 只做聚合与适配，不承载业务规则；总超时必须小于各上游超时之和；降级必须显式标记；契约变更走生成与漂移检查，不手改客户端。
