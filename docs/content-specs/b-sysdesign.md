# 课时规格：b-sysdesign 系统设计面试案例

## 0. 元数据

| 字段 | 值 |
| --- | --- |
| 课时 ID | `b-sysdesign` |
| 标题 | 系统设计面试案例 |
| 所属阶段 | 附录 · 数据结构、性能、架构、工程与 AI 基础设施 |
| 时长 | 70 分钟 |
| 先修 | `s0`-`s7` 全部核心机制 |
| 对应批次 | B7.4 |

## 1. 出口能力

1. 用固定结构回答系统设计题：澄清 → 估算 → API → 数据 → 架构 → 瓶颈 → 失败 → 取舍。
2. 在短链、Feed、秒杀、订单、AI 助手中识别共同模式与差异。
3. 主动说出失败模式与降级，而不是只画 happy path。
4. 控制表达节奏：先框架，后细节，随时接受追问。

## 2. 起点与误解

- 已经知道：缓存、队列、分片、幂等、降级等机制在核心阶段都讲过。
- 常见误解：
  - 「一上来就画架构图」——没有澄清规模与约束，画得越多错得越多。
  - 「方案越复杂越显水平」——面试官更关心取舍与失败模式。
  - 「案例题要背标准答案」——同一道题在不同规模下答案不同。

## 3. 范围边界

- 本讲只讲：答题结构、五个案例的共性与差异、失败模式与表达。
- 不讲：新机制；案例需要的机制引用 S0-S7 对应课时。
- 与相邻讲分工：b-sysdesign 只做案例与表达训练，机制讲解在核心阶段。

## 5. 概念检查

- C1 单选：系统设计第一步应该做什么。
- C2 多选：秒杀必须处理哪些问题。
- C3 单选：AI 助手与短链在设计上的最大差异。

## 6. 练习

- 方案题：两个案例的完整回答；自检清单覆盖需求澄清、规模估算、API、数据模型、架构图、瓶颈、失败模式、取舍、演进。
- 不设代码题；正文中的检查函数只作演示。

## 7. 事实与夹具

- 事实：面试案例没有唯一答案；不同公司规模与约束不同；案例只做表达训练。
- 不新增夹具。
