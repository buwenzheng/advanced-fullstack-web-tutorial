# 课时规格：b-incident 故障处理、复盘与面试表达

## 0. 元数据

| 字段 | 值 |

| 课时 ID | `b-incident` |
| 标题 | 故障处理、复盘与面试表达 |
| 所属阶段 | 附录 · 数据结构、性能、架构、工程与 AI 基础设施 |

## 1. 出口能力

1. 按故障分级启动响应，先止损再定位。
2. 写无责复盘：时间线、影响、根因、行动项。
3. 在面试中讲清一次故障与一次架构取舍。
4. 识别「人祸」与「系统性缺陷」，把行动项落到机制。

## 2. 起点与误解

- 已经知道：监控、日志、告警、分布式失败的基本机制。
- 常见误解：
  - 「先找根因再处理」——故障中先止损，根因可以后续定位。
  - 「复盘就是追责」——无责复盘关注机制，不关注个人。
  - 「行动项写成加强意识」——不可验证的口号不会改变系统。

## 3. 范围边界

- 本讲只讲：故障分级、响应流程、无责复盘、行动项质量、面试表达。
- 不讲：分布式失败机制（`e1-failures`）、可观测性工具配置（`m3-otel`）。
- 与相邻讲分工：b-incident 讲流程与表达，核心课讲机制与工具。

## 5. 概念检查

- C1 单选：故障响应的第一优先级。
- C2 多选：无责复盘必须包含什么。
- C3 单选：好的行动项应该是什么样。

## 6. 练习

- 方案题：故障复盘 + 面试表达；自检清单覆盖时间线、影响范围、止损动作、根因、行动项与 owner、机制改进、2 分钟表达。
- 不设代码题；模板块只作示范。

## 7. 事实与夹具

- 事实：故障分级因组织而异；无责复盘不等于无责任；面试表达没有统一模板。
- 不新增夹具。
