## 1. 出口能力

1. 解释 Agent loop、工具/MCP、权限与沙箱、上下文压缩。
2. 区分 IDE/CLI/CI 三类工具的适用任务与风险。
3. 设计 review 政策、provenance、许可与安全边界。
4. 用 M1-M5 成熟度与度量指标制定团队落地路线。

## 2. 起点与误解

- 已经知道：五层模型、验证门、CI 与代码评审。
- 常见误解：
  - 「个人提效等于组织提效」——没有规范与度量，收益无法复用。
  - 「Agent 权限越大越能干」——高风险工具必须最小权限与沙箱。
  - 「生成行数是生产力」——虚荣指标，首次通过率与缺陷逃逸才有意义。
  - 「上 Agent 就是成熟」——成熟度是控制能力，不是工具数量。

## 3. 范围边界

- 本讲只讲：Agent loop、工具与权限、IDE/CLI/CI 分工、provenance 与许可、review 政策、度量、M1-M5 路线。
- 不讲：具体 IDE/CLI 产品评测、MCP 协议实现细节、m4-coding-system 的五层模型与验证门。
- 与相邻讲分工：m4-coding-system 讲控制回路；本讲讲组织落地与治理。
