# 课时规格：a10 技术方案与架构决策（ADR）

## 0. 元数据

| 字段 | 值 |
| --- | --- |
| 课时 ID | `a10` |
| 标题 | 技术方案与架构决策（ADR） |
| 所属阶段 | 附录 · 数据结构、性能、架构、工程与 AI 基础设施 |
| 时长 | 70 分钟 |
| 先修 | `s5-l1`（模块边界）、`s5-l3`（分布式失败） |

## 1. 出口能力

1. 写出可评审的 ADR：问题、约束、备选、决策、后果、反悔条件。
2. 区分决策记录、设计文档与 RFC。
3. 用 ADR 记录 LinkHub 的三个关键取舍。
4. 在评审中接受质疑并留下决策依据。

## 2. 起点与误解

- 已经知道：模块边界、异步与一致性取舍、评审流程的基本概念。
- 常见误解：
  - 「ADR 就是设计文档」——ADR 记录决策与后果，不重复完整设计。
  - 「只写选了什么」——不写备选与反悔条件，决策无法复核。
  - 「决策写完就结束」——没有 owner 与复盘，ADR 会与实现脱节。

## 3. 范围边界

- 本讲只讲：ADR 结构、与设计文档/RFC 的区别、备选对比、反悔条件、评审。
- 不讲：模块边界本身（`s5-l1`）、分布式失败机制（`s5-l3`）、具体团队流程工具。
- 与相邻讲分工：a10 讲决策记录与评审，核心课讲模块与失败机制。

## 5. 概念检查

- C1 单选：ADR 中「反悔条件」的作用。
- C2 多选：一份可评审 ADR 必须包含什么。
- C3 单选：ADR 与设计文档的区别。

## 6. 练习

- 方案题：LinkHub 三份 ADR；自检清单覆盖问题陈述、约束、至少两个备选、决策、后果、反悔条件、影响面、评审记录。
- 不设代码题；模板块只作示范。

## 7. 事实与夹具

- 事实：ADR 格式有多种；状态机（提议/接受/废弃/取代）常见；没有强制标准。
- 不新增夹具。
