# 毕业项目规格：p-graduation LinkHub

> 来源：`docs/implementation/08-graduation.md`。本页只定义项目说明、模板与验收标准；真实系统由学员在 p1-p7 的同一代码库中增量完成。

## 1. 页面结构

- 项目 hero：标题、brief、stack、里程碑进度。
- 左侧：你要交付什么、实施路线、11 个里程碑清单。
- 右侧：交付物、验收自评、进阶挑战、项目笔记。
- 底部：答辩模板库（6 份，可复制代码块，不依赖下载）。

## 2. 里程碑字段

每个里程碑必须包含：

| 字段 | 要求 |
| --- | --- |
| `id` | 固定 `m1`…`m11` |
| `title` | 与课程规划 M1-M11 一致 |
| `desc` | 在既有代码库上的增量，不写成实现教程 |
| `delivery` | 具体交付物 |
| `acceptance` | ≥2 条可观察验收，写清命令、行为或阈值 |
| `evidence` | ≥2 条可复现证据（命令、报告、截图、trace） |
| `reuse` | 复用的阶段项目 ID，必须符合映射 |
| `related` | 关联阶段或讲次链接 |
| `criteria` | 一句话验收摘要 |

**复用映射**：M1→p2；M2→p1/p2；M3→p3/p5（统计服务来自 p5）；M4→p3/p4；M5→p4；M6→p4；M7→p6；M8→p6；M9→p2/p6；M10→p7；M11→p1-p7。不得新建第二套服务。

**M11 额外要求**：三个取舍、两个失败模式、一次真实回滚、一次故障恢复、AI 功能可回滚；材料数字与报告一致。

## 3. 模板

| 模板 | 必含 |
| --- | --- |
| ADR | 背景、约束、≥2 个备选、决策、正面/负面后果、反悔条件 |
| 容量模型 | 峰值/读写比/命中率/单实例基线、平均/峰值/故障三场景、冗余、成本表、压测验证与瓶颈迁移 |
| 故障演练 | 时间线、影响、根因、行动项（owner/截止/可验证）、预防机制 |
| AI 评估报告 | 评估集版本与规模、四类用例、阈值与结果、失败样例、修复回归、成本、降级演练 |
| AI 协作记录 | 五层（任务/上下文/执行/验证/系统）、≥3 失败案例、≥1 次回滚或重做 |
| 答辩评分表 | 7 维、硬门槛、6 个必问问题、5 个扣分项、结论规则（平均 ≥3.5 且无单项 <3） |

## 4. 内容边界

- 不重写 p1-p7；不教实现步骤，只给验收与证据要求。
- 每个结论要有代价与边界；每个数字要能回到命令或报告。
- 不引入核心课与附录未讲过的机制；需要时链接到对应课时。
- 模板是填空骨架，不是范文；不得出现真实密钥、个人信息或生产数据。

## 5. 验收

- `node tools/audit-content.mjs`：11 个里程碑字段齐全、复用映射正确、6 份模板齐全且必含项完整。
- `node tools/check-links.mjs`：关联链接 0 断链。
- 浏览器：1440px 与 390px 无横向滚动；11 个里程碑可勾选、可写笔记；6 份模板可复制；控制台 0 错误。
