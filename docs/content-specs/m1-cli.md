## 1. 出口能力

1. 用进程、端口与日志工具定位「服务起不来」「端口被占」「DNS 不对」三类常见故障。
2. 解释常见信号与退出码，知道什么时候不该 `kill -9`。

## 2. 学习者起点与常见误解

- 已经知道：`npm run dev`、`curl`、终端里按 Ctrl-C、`console.log`；遇到端口冲突时偶尔重启电脑。
- 常见误解：
  - 「端口被占就 `kill -9`。」——可能杀错进程、丢缓冲、留下锁与子进程。
  - 「`curl` 超时就是服务挂了。」——可能是 DNS、连接被丢弃、TLS 握手卡住或服务端排队。
  - 「退出码不重要，看日志就行。」——自动化脚本与进程管理器首先看退出码。
  - 「`0.0.0.0:3000` 和 `[::]:3000` 是同一行。」——IPv4 与 IPv6 监听是两条记录，可能只有一条生效。
  - 「`lsof` 的输出每一行都带 PID。」——权限不足时看不到进程信息，不能把整行丢掉。

## 3. 范围边界

- 本讲只讲：
  - 进程、PID、父子关系、前台/后台、退出码；
  - `ss`、`lsof`、`ps`、`kill` 的基本用法；
  - 信号 TERM/INT/KILL/HUP 的语义与选择；
  - 端口占用、DNS/hosts、`curl` 失败类型的排查顺序；
  - 日志检索与 requestId 关联；
  - 文件描述符、`ulimit`、TIME_WAIT 与临时端口的直觉。
- 本讲不讲：
  - 内核网络参数、eBPF、systemd 深入（交给 b-linux）；
  - 容器与编排（交给 S4）；
  - 应用层错误契约与鉴权（交给 S2）；
  - 队列、重试与削峰（交给 S3/S5）。
- 与相邻讲的分工：
  - `m1-http` 讲请求在网络上经过哪几段；本讲讲怎么在机器上观察与操作；
  - `m1-runtime` 讲运行时内部排队；本讲讲进程、端口与日志；
  - `s1-*` 讲数据层；本讲不涉及数据库内部。

## 5. 概念检查（3 题）

### C1

- ID：`m1-cli-check-1`
- 类型：single
- 题干：在 Linux 上，哪个命令可以直接查看监听端口及其对应的 PID？
- 选项：`ss -ltnp`（正确）、`ls -l`、`curl -I`、`dig`（错误）。
- 解析要点：`ss -ltnp` 列出 TCP 监听端口并显示进程；`lsof -i` 也可用，但本题只给一个正确项。`ls` 看文件，`curl` 发请求，`dig` 查 DNS。
- 对应 objective：O1/O3。

### C2

- ID：`m1-cli-check-2`
- 类型：multi
- 题干：关于信号与退出码，以下哪些说法正确？
- 选项：
  - A. SIGTERM 默认终止进程，但进程可以注册处理函数做清理（正确）
  - B. SIGKILL 不能被捕获或忽略，进程没有机会执行清理（正确）
  - C. SIGINT 只能由 `kill -9` 发送（错误）
  - D. 退出码 0 通常表示成功，非 0 表示失败（正确）
  - E. `kill -9` 会等待进程把日志刷完再退出（错误）
- 解析要点：TERM 可被处理，KILL 不可捕获；INT 通常来自 Ctrl-C；退出码约定 0 成功；KILL 不等待清理。
- 对应 objective：O2。

### C3

- ID：`m1-cli-check-3`
- 类型：single
- 题干：`curl` 报 `Connection refused`，最先应该查什么？
- 选项：
  - A. 目标端口是否有进程监听、服务是否启动（正确）
  - B. TLS 证书是否过期（错误）
  - C. 响应体里的业务错误码（错误）
  - D. 浏览器缓存是否命中（错误）
- 解析要点：连接被拒绝通常意味着目标机器可达但端口没有监听，或本机服务未启动；TLS/HTTP 发生在连接之后；连接失败时没有响应体。
- 对应 objective：O1/O4。

## 6. 代码题（1 题，Node/Python 双轨）

- 题号：`m1-cli-ex-1`
- 标题：解析监听端口
- 业务场景：p-m1-probe 的本地测试与排障脚本需要把 `ss -ltnp` 或 `lsof` 的文本转成结构化列表，供后续判断端口是否被占、进程是否重复。
- 函数/接口契约：

```js
parseListeners(output)
```

返回 `[{ address, port, pid, process }]`：

- `address`：去掉 IPv6 方括号的地址字符串；
- `port`：数字端口；
- `pid`：数字 PID；权限不足或没有进程信息时为 `null`；
- `process`：进程名；权限不足或没有进程信息时为 `null`；
- 跳过空行与无法识别的行；
- 只保留监听（`LISTEN` / `(LISTEN)`）记录；
- 按端口升序排序；端口相同时保持输入顺序（稳定排序）。

输入样例：

```text
LISTEN 0 511 0.0.0.0:3000 0.0.0.0:* users:(("node",pid=1234,fd=23))
LISTEN 0 511 [::]:3000 [::]:* users:(("node",pid=1234,fd=24))
LISTEN 0 511 127.0.0.1:5432 0.0.0.0:*
node 4321 alice 23u IPv4 0x1234 0t0 TCP 127.0.0.1:8080 (LISTEN)
```

- Node starter 要点：只用 IPv4 正则，process 固定为 `node`，不排序，无法识别 IPv6、无 users、lsof。
- Node solution 要点：按行判断 `LISTEN` 或 `(LISTEN)`；ss 取第 4 列本地地址，lsof 找 `TCP`/`TCP6` 后的本地地址；用 `lastIndexOf(':')` 或正则拆分 IPv6；缺失 users 时填 `null`；最后按端口稳定排序。
- 测试用例（7 条）：

| # | 场景 | 输入 | 期望 |
| --- | --- | --- | --- |
| 1 | IPv4 ss | `LISTEN 0 511 0.0.0.0:3000 0.0.0.0:* users:(("node",pid=1234,fd=23))` | `{address:'0.0.0.0',port:3000,pid:1234,process:'node'}` |
| 2 | IPv6 ss | `LISTEN 0 511 [::]:3000 [::]:* users:(("node",pid=1234,fd=24))` | `{address:'::',port:3000,pid:1234,process:'node'}` |
| 3 | 同一进程多行 | 上两行同时输入 | 两个条目，顺序保持输入顺序 |
| 4 | 权限不足无 users | `LISTEN 0 128 127.0.0.1:5432 0.0.0.0:*` | `{address:'127.0.0.1',port:5432,pid:null,process:null}` |
| 5 | 畸形行跳过 | 空行、`LISTEN garbage`、`not a listener` 与一条有效行 | 只返回有效行 |
| 6 | 端口按数字排序 | 5432、80、3000 三条 | 80、3000、5432 |
| 7 | lsof 风格 | `node 4321 alice 23u IPv4 0x1234 0t0 TCP 127.0.0.1:8080 (LISTEN)` | `{address:'127.0.0.1',port:8080,pid:4321,process:'node'}` |

- 测试设计说明：用例 2/3 区分 IPv6 与多行；用例 4 区分权限不足时丢整行；用例 6 区分字符串排序（会得到 3000、5432、80）；用例 7 区分只支持 ss 的实现。
- Python 差异：`parse_listeners(output)` 返回 `list[dict]`；用命名分组正则；`int(port)`；`sorted(..., key=lambda item: item["port"])` 稳定排序；无 users 时用 `None`。
- 常见错误：把 `0.0.0.0:*` 当本地端口；IPv6 地址按第一个冒号切；权限不足时丢整行；用字符串排序。

## 7. 方案题

- 题号：`m1-cli-ex-2`
- 场景：本地 `npm run dev` 报 `EADDRINUSE`；部署后 `curl` 超时；域名解析到旧 IP。请写一份故障排查 runbook。
- 自检清单（8 条）：
  1. 先确认现象类型（拒绝、超时、DNS、5xx），不先改代码；
  2. 用 `ss`/`lsof` 确认进程与端口；
  3. 确认启动命令、工作目录与环境变量；
  4. 用 `dig`/`getent`/`curl --resolve` 区分解析与连接；
  5. 每一步都有明确的判据与下一步；
  6. 不直接 `kill -9`，先尝试优雅终止；
  7. 记录时间线与每次变更；
  8. 给出修复后的验证命令。
- 参考要点：症状 → 层 → 命令 → 判据 → 下一步；端口冲突先找占用者，DNS 问题先确认解析结果，超时要区分连接建立与响应等待。
- 常见浅答案：把一切归因于「服务挂了」；直接重启；不记录改了什么。
