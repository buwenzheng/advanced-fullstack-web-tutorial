## 1. 出口能力

1. 解释推理的 prefill/decode、KV cache、批处理与量化的成本影响。
2. 区分 GPU/CPU 推理与模型路由的适用场景。
3. 解释 HNSW/IVF/PQ 的召回、内存与延迟取舍。
4. 为 LinkHub 做推理容量与成本模型，并说明隐私与部署边界。

## 2. 起点与误解

- 已经知道：模型调用、流式输出、RAG 检索与评估的基本流程。
- 常见误解：
  - 「只看每百万 token 单价就能估成本」——忽略输入输出比例、上下文长度、重试与缓存。
  - 「量化一定划算」——质量损失与任务敏感度需要评估。
  - 「上 GPU 就快」——吞吐、延迟、显存与批处理策略共同决定，容量按峰值与故障场景算。

## 3. 范围边界

- 本讲只讲：推理两阶段、量化与硬件、模型路由、向量索引、容量与成本、部署与隐私。
- 不讲：应用集成（`m4-llm/l2`）、训练与微调、具体厂商评测与价格对比。
- 与相邻讲分工：b-ai-infra 讲基础设施素养与成本模型，核心课讲应用怎么接。

## 5. 概念检查

- C1 单选：prefill 与 decode 哪个更受输入长度影响。
- C2 多选：影响推理成本的因素。
- C3 单选：HNSW 参数增大时召回与内存如何变化。

## 6. 练习

- 方案题：LinkHub 推理容量与成本模型；自检清单覆盖请求量、输入/输出 token、模型路由、缓存、批处理、GPU/CPU、峰值、降级、隐私、成本上限。
- 不设代码题；成本估算函数只作演示。

## 7. 事实与夹具

- 事实：推理框架与硬件差异大；量化会损失质量；索引参数影响召回与内存；价格会变。
- 不新增夹具。
