## 1. 出口能力

1. 设计分层流水线：快速反馈在前，慢测试在后，失败阻断合并。
2. 选择蓝绿/金丝雀/滚动发布，并定义回滚触发条件。
3. 用 expand-contract 保证数据库变更可回滚。
4. 用特性开关隔离发布与上线，并处理开关债务。

## 2. 学习者起点与常见误解

- 已经知道：GitHub Actions、PR 预览环境、前端静态部署。
- 常见误解：
  - 「CI 通过就等于可以上线。」——CI 验证代码，不验证容量、数据与发布风险。
  - 「回滚就是切回旧镜像。」——数据库迁移与消息格式可能不可逆。
  - 「蓝绿一定比金丝雀安全。」——蓝绿切换快，但新版本同时承接全量流量。
  - 「特性开关开完就不用管。」——开关会形成债务，长期分支与组合爆炸。
  - 「灰度只看错误率。」——延迟、业务指标与依赖饱和度同样可能先恶化。

## 3. 范围边界

- 本讲只讲：流水线关卡、测试分层、发布策略、expand-contract、特性开关与回滚。
- 本讲不讲：测试策略与工程效能（a11）、具体 CI 产品教程、Kubernetes 发布控制器细节。
- 与相邻讲的分工：s4-l3 提供可部署镜像；本讲决定如何安全上线；a11 深入测试体系。

## 6. 代码题：特性开关判定

契约：`evaluateFlag(flag, context = {})`。

- `flag` 支持 `key`、`enabled`、`percentage`、`allowlist`、`denylist`、`killSwitch`。
- 返回 `{ enabled, reason }`，优先级固定：未知 flag → kill switch → 黑名单 → 白名单 → `enabled === false` → `percentage === 100` → `percentage` 为 0/缺省 → 无 userId → 分桶。
- 哈希统一 FNV-1a 32-bit，对 UTF-8 字节；桶 = `hash(flag.key + ':' + userId) % 100`，`桶 < percentage` 命中。
- 匿名用户不能进入百分比灰度；白名单/黑名单必须有 userId 才生效。

测试（7）：全开/全关；白名单；黑名单；百分比稳定；kill switch 覆盖；匿名用户关闭；未知 flag 默认关。

Python 差异：`.encode('utf-8')`、`& 0xFFFFFFFF`、dict 返回；不得使用 `hash()` 或 `hashlib` 代替约定算法。
