## 2. 学习者起点与常见误解

- 已经知道：`Map`、前端 `memo`、HTTP 缓存头的基本含义；发过带 `Cache-Control` 的请求；见过 Redis 作为缓存的用法。
- 常见误解：
  - 「缓存就是加个 `get`，没有再查库。」——难点在失效与并发回源，不在读。
  - 「TTL 越长命中率越高，所以越长越好。」——TTL 决定最坏情况下多久看到旧值，是业务一致性预算。
  - 「更新数据库后删缓存就一定一致。」——删除失败、并发读回填、主从延迟都会留下旧值；要写清失败处理与最坏窗口。
  - 「缓存挂了直接报错最安全。」——读缓存故障通常应降级回源，除非回源会把数据库打垮；这是显式取舍。
  - 「加缓存能解决慢查询。」——缓存只减少回源次数；单次回源仍慢时，热点过期瞬间会更糟。
  - 「CDN 和 Redis 是一回事。」——生命周期、失效范围与一致性模型都不同；边缘缓存在 m3-edge。

## 3. 范围边界

- 本讲只讲：
  - 应用层缓存（进程内 + Redis 类共享缓存）的读写模式；
  - Cache-Aside、TTL、主动失效、空值缓存、single-flight、TTL 抖动；
  - 穿透/击穿/雪崩与热点 key；
  - 命中率、回源 QPS、P99 的度量与验收；
  - LinkHub 跳转读路径的缓存方案。
- 本讲不讲：
  - CDN/边缘缓存、SWR 与前端缓存策略（m3-edge）；
  - Redis 集群、持久化、主从切换（基础设施附录）；
  - 分布式锁与一致性协议（m3-resilience、s5）；
  - 具体框架的缓存注解与产品配置。
- 与相邻讲的分工：本讲讲「缓存怎么放、怎么失效、怎么防打穿」；m3-queue 讲「写路径如何异步化」。

## 5. 概念检查（3 题）

### C1

- ID：`m3-cache-check-1`
- 类型：单选
- 考点：LinkHub 跳转读多写少，应选哪种模式
- 正确项：Cache-Aside，读时回源并回填，写后主动失效
- 解析要点：Write-Through 增加写路径依赖；Write-Behind 引入丢失风险；只加 TTL 不主动失效会扩大旧值窗口。

### C2

- ID：`m3-cache-check-2`
- 类型：多选
- 考点：穿透、击穿、雪崩的防护
- 正确项：空值缓存/布隆过滤防穿透；single-flight 或逻辑过期防击穿；TTL 抖动防雪崩；热点 key 拆分与本地缓存
- 解析要点：只调大 TTL 同时放大三者；加锁不是唯一解；每个防护都要说清成本。

### C3

- ID：`m3-cache-check-3`
- 类型：单选
- 考点：更新链接后缓存失效的顺序与失败处理
- 正确项：先提交数据库事务，再删除缓存；删除失败进入重试/告警，并接受 TTL 兜底
- 解析要点：先删缓存再提交事务会被并发读回填旧值；事务未提交就删缓存同样有窗口；失败必须可观测。

## 6. 代码题：带防护的缓存

- 契约：`createCache({ ttl = 60000, max = 500, now = Date.now } = {})`
  - `get(key, loader)`：命中返回值；未命中调用 `loader()` 并缓存；同一 key 并发 miss 只调用一次 loader；loader 抛错不缓存，错误传给所有等待者。
  - `set(key, value, { ttl } = {})`：显式写入，可覆盖 TTL。
  - `delete(key)`：主动失效。
  - 负缓存：`loader` 返回 `null`/`undefined` 时按 `negativeTtl`（默认 5000ms）缓存。
  - `now` 注入，测试不得依赖真实时间。
- 规则：
  - 过期条目在读取时删除；容量超过 `max` 时淘汰最早写入的 key（教学实现，不要求 LRU）。
  - single-flight 的 inflight 表必须在成功与失败后都清理。
  - 负缓存只缓存「确实不存在」的空结果，不能把异常当空值。
- 测试（≥6）：
  1. 命中后不再调用 loader；
  2. 过期后重新调用 loader；
  3. 并发 miss 只调用一次 loader；
  4. loader 失败不缓存，下一次会重试；
  5. 空结果按 negativeTtl 缓存，过期后重试；
  6. `delete` 后下一次回源；
  7. 容量上限触发淘汰，旧 key 回源。
- 测试设计说明：第 3 条用可控 Promise 挂起 loader，先并发发起两次 `get` 再释放；第 4 条连续两次失败后成功，断言调用次数；第 5 条用注入时钟跨越 negativeTtl；第 7 条用 `max=2` 验证最早写入被淘汰。
- Python 差异：async 版本；`asyncio.Lock` 或共享 `asyncio.Task` 实现 single-flight；字典 + 注入 `now`（毫秒整数）；`None` 表示未命中与「缓存空值」需要哨兵值区分，正文 note 必须说明。
- 常见错误：缓存 Promise 但 `finally` 不清理；loader 失败也写入缓存；把 `None` 当未命中导致负缓存失效；并发 miss 各自回源。

## 7. 方案题：LinkHub 缓存方案

场景：跳转接口 QPS 是创建接口的 100 倍，数据库在晚高峰出现慢查询；短链目标可修改，要求修改后最迟 30 秒生效。
