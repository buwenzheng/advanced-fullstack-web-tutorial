## 1. 出口能力

1. 区分 CSR/SSR/SSG/流式渲染的收益与成本，并按页面特征选择。
2. 解释水合成本与可交互时间，避免「首屏很快、点了没反应」。
3. 用 LCP/INP/CLS 与性能预算管理体验，而不是只看加载完成。
4. 区分实验室数据与 RUM，知道各自的盲区。

## 2. 学习者起点与常见误解

- 已经知道：浏览器加载流程、HTTP 缓存、前端打包的基本概念。
- 常见误解：
  - 「SSR 一定比 CSR 快。」——SSR 只优化首屏 HTML，水合仍要执行脚本。
  - 「首屏渲染完就可交互。」——水合完成前点击可能无响应。
  - 「看 Lighthouse 分数就够了。」——实验室数据无法覆盖真实设备与长任务。
  - 「全站都上 SSG。」——个性化与新鲜度要求会让 SSG 失效。
  - 「性能预算就是压缩资源。」——预算是 p75 指标门槛，不是构建体积清单。

## 3. 范围边界

- 本讲只讲：四种渲染模式、水合、CWV、性能预算、关键路径与资源提示、实验室 vs RUM。
- 本讲不讲：框架语法、组件库、构建工具教程；RUM 采集实现与 trace 串联（s6-l4）；CDN 配置（s6-l4）。
- 与相邻讲的分工：s4-perf 讲后端压测与瓶颈；本讲讲浏览器侧渲染与体验指标；s6-l4 讲边缘与真实用户监控。

## 6. 代码题：渲染策略决策 + 性能预算

契约：

- `chooseRenderStrategy(page)`：输入 `{ requiresAuth, personalization, freshnessSec, seo, interactivity }`。
  - `personalization ∈ {'none','low','high'}`，缺省 `'none'`；`freshnessSec` 缺省 `Infinity`；其余 boolean。
  - 固定优先级：
    1. `personalization === 'high'` → `stream`；
    2. `seo === true && freshnessSec <= 60` → `ssr`；
    3. `seo === true` → `ssg`；
    4. `requiresAuth === true` → `csr`；
    5. 默认 → `csr`。
- `checkBudget(samples, budget)`：`samples = { lcp?: number[], inp?: number[], cls?: number[] }`。
  - p75 用最近秩：升序后 `index = ceil(0.75 * n) - 1`；`n === 0` 不取。
  - 返回 `{ pass, violations: [{ metric, p75, budget, ratio, reason? }] }`。
  - `p75 <= budget` 通过；空/缺失样本记 `p75: null, reason: 'NO_DATA'` 并判失败。
  - `ratio = (p75 - budget) / budget`；按 ratio 降序，ratio 相同按 `lcp → inp → cls` 固定顺序；NO_DATA 排在最后。

测试（8）：营销页 ssg；个性化看板 stream（即使 seo）；登录工具页 csr；新鲜内容 ssr；全部达标通过；p75 等于预算通过；空样本 NO_DATA 失败；多违规按 ratio 排序且同 ratio 顺序稳定。

Python 差异：纯函数 + 手写最近秩；浮点比较；返回 dict；测试数量一致。

## 7. 方案题：LinkHub 渲染与 CWV 预算

自检清单（10）：页面分类；每类策略与理由；数据获取位置；水合边界；LCP/INP/CLS 预算；资源提示；图片/字体；实验室与 RUM 双数据源；降级；预算进 CI。
