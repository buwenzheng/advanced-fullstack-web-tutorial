## 1. 出口能力

1. 解释 tokens、上下文窗口、消息角色与截断对行为与成本的影响。
2. 用 SSE 实现可增量消费的流式输出，处理分块边界、CRLF、多行与结束标记。
3. 设计结构化输出校验、超时、重试、幂等与模型路由。
4. 用 token 计量与成本表控制单请求与单租户预算。

## 2. 起点与误解

- 已经知道：HTTP、BFF、超时与重试、结构化日志与 trace。
- 常见误解：
  - 「上下文越大越好」——窗口有限，输入输出都计费，噪声会降低指令遵循。
  - 「流式等于实时」——网络分块与首 token 延迟决定体感，SSE 只解决传输。
  - 「失败就重试」——非幂等请求重试会重复扣费或重复写入。
  - 「模型返回的 JSON 可以直接入库」——必须 schema 校验与降级。

## 3. 范围边界

- 本讲只讲：tokens/角色/窗口、结构化输出、SSE、网关路由、预算、幂等重试、降级。
- 不讲：训练/微调、推理服务内部、KV cache 与量化（a13）、厂商 SDK、提示词大全。
- 与相邻讲分工：s6-l1 讲 BFF 聚合；本讲讲模型调用与流式网关；s6-l4 讲 trace 与发布。

## 6. 代码题：SSE 解析 + 流式网关

契约：

- `parseSSE(chunks)`：字符串分块数组 → 事件数组 `{ id?, event, data }`；多行 `data:` 以换行拼接；空行派发；支持 LF/CRLF；忽略注释行；`[DONE]` 输出 `{ event: 'done', data: '' }`。
- `createGateway({ providers, pricing, budget, maxRetries = 1 })`：
  - 路由：`risk === 'high' || complexity === 'high'` 走 `strong`，否则 `cheap`。
  - 成本：`ceil((inputTokens * inputPer1k + outputTokens * outputPer1k) / 1000)`，整数分。
  - `cost > budget` 抛 `BUDGET_EXCEEDED`，不重试。
  - 仅 `err.retryable === true` 且请求带 `idempotencyKey` 才重试，最多 `maxRetries` 次。
  - provider 缺 usage 或负数 token 抛 `INVALID_PROVIDER_RESPONSE`。
  - 返回 `{ text, model, usage, cost, attempts }`。

测试（10）：单块 SSE；跨块切断；多行 data；CRLF 与注释；`[DONE]`；低复杂度走 cheap；高风险走 strong；预算拒绝；幂等重试一次；非幂等不重试。

Python 差异：生成器解析；`asyncio` 网关；异常映射；成本用整数分。
