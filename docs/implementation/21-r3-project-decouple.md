## 1. 阶段边界

### 1.1 本阶段做

- 重写各块 `project.ts`（及 `x-linkhub`）的标题、目标、里程碑、验收，符合规划：
  - `p-m1-probe`、`p-m2-data`、`p-m2-api`、`p-m3-ship`、`p-m3-web`、`p-m4-ai`、`p-e1-stats`、`x-linkhub`
- `p-m3-ship`：明确可分两里程碑组（缓存异步 / 观测发布）；可选「真机部署」加分档（不挡结业）
- `x-linkhub`：里程碑映射规划 X1–X10；结业档 **全栈 / AI 全栈 / 分布式** 写进项目数据或旁路 JSON
- **路径结业映射表**（写入 `docs/reviews/track-restructure/r3/path-completion-map.md`）：路径 A/B/C/D 各自「证明物」↔ 项目里程碑 ID，供 R4「路径完成度」使用；**必须用 §3.1 表样例填实，禁止只写「见规划」**
- 扫课时/项目正文：删除或改写「必须先完成上一阶段 LinkHub / 本阶段必须接续 pN」类硬耦合句；改为「建议复用本块域模型」或「集成见 X」
- 扫 `docs/content-specs/**` 与报告相关文案中的线性「八阶段」表述
- M3 章1 保留「何时不该拆」方案题指向（可与现有 design 题对齐，不强制新题）
- 更新项目页展示：多项目块（M2）、选修标记（E1）、X 档位说明
- 证据：`docs/reviews/track-restructure/r3/`

> **依赖说明**：G-R3 通过后才进入 R4，避免路径 UI 链到旧叙事。

### 1.2 本阶段不做

- 不新建真实 Git 外部仓库（LinkHub 工程轨属后续加厚）
- 不改判题引擎与练习断言（除非文案引用旧项目名）
- 不重做路径导航信息架构（R4）
- 不扩写 a9 案例库、RAG 变体（加厚项）

### 1.3 结束形态

- 只学 M1→M2→M3 章1 的学员，项目说明可自洽完成，不被要求先做 E1/X
- 毕业页能区分三档结业依赖
- `content:validate` / 项目相关单测绿

## 3. 文案解耦规则

| 禁止（硬耦合） | 替换为 |
| --- | --- |
| 「在上一阶段 LinkHub 仓库上继续」 | 「在本块 `p-m2-api`（或你的等价服务）上增量」 |
| 「学完 S0–S7 再做毕业」 | 「完成路径 B 或 C 后进入 X；或按 X 档补依赖」 |
| 「p5 必须从 p3 BullMQ 升级」 | 「E1 项目可从 M2 域模型起步；若已有异步版可对照升级」 |
| 「附录课」 | 「工具箱」 |

允许保留：**示例域**继续用短链/LinkHub 名词，只要不强制学习顺序。

扫描命令建议：

```bash
rg -n "上一阶段|必须先|接续 p[0-9]|S0.|八个核心|附录" web/scripts/content -g "*.ts"
```

命中后逐条人工判断，结果记入 `r3/coupling-scan.txt`。

## 4. 项目 brief 验收标准（每块）

每个项目对象至少含：

1. 目标（块出口对齐）  
2. 里程碑列表（可观察验收，非「做完」）  
3. **显式先修**：block/chapter，而不是隐式「学完前面所有课」  
4. **非目标**：本项目不要求的能力（例如 `p-m2-api` 不要求 Outbox）  
5. 与 X 的关系：可选「本项目产出可带入 X#n」
