# 批次任务卡模板

> 每个可执行任务一张卡。卡是给执行 Agent 的最小上下文单元：只读这张卡与卡里引用的文档，就能稳定完成。  
> 字段定义见 `docs/reviews/track-restructure/execution-playbook.md` §3。

## 任务卡

- **类型**：engine / content / app / validation / docs / review  
- **影响半径**：L0 / L1 / L2 / L3 / L4 / L5（见执行手册）  
- **依赖（上游）**：前置任务 ID 或评审门  
- **关联（下游/同批）**：谁会消费本产出；同批哪些任务禁止并行  
- **实现要点**（必须具体到文件/字段/算法）：

- **输入**：  
  - 大纲：`docs/curriculum-plan.md#...`  
  - 批次文档：`docs/implementation/...`  
  - 已有文件：  
- **产出**：  
  -  
- **约束**：  
  - 只允许改：  
  - 不允许改：  
  - 判题 / localStorage 键名 / 路由形态：  
- **执行序位**：本批第 __ 步；不能提前的原因：  
- **测试**（写命令与预期；对照执行手册测试阶梯）：  
  - T0–T6 中最低层：  
  - 命令：  
  - 单测/夹具/E2E/手工：  
- **Review**：  
  - 自检：

- **回滚**：  
- **预计批量**：涉及几讲/几个文件  

## 批次收尾检查

- [ ] 本批所有任务卡「测试」项已跑且绿（或已知债入库）  
- [ ] G-R* 验收清单已勾  
- [ ] 证据已写入 review  
- [ ] 未破跨批质量不变量（判题语义、键名、路由六形态、45/3400）  
- [ ] 下游接口契约已更新（若有）  
- [ ] 下一批依赖已满足；**未**抢跑更高影响半径
