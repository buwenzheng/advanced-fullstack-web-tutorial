# 实施总纲：AI 时代资深全栈课程重建

> 本文件是实施阶段的唯一调度依据。课程目录以 `docs/curriculum-plan.md` 为准，本文件只回答「按什么顺序、拆成哪些模块、每块怎么验收、什么时候必须停下来 review」。

## 1. 目标与范围

### 1.1 最终交付物

一个保持私有的学习站，包含：

- 8 个核心阶段（S0-S7）、32 讲核心课；
- 1 个毕业项目（LinkHub，11 个里程碑）；
- 13 讲附录（a1-a13）；
- 45 讲全部具备：3 道概念检查 + 至少 1 道可验证练习（代码/SQL/方案）；代码题一律 Node/Python 双轨，SQL 题按课程表，方案题按阶段配置；
- 课程表「练习」列是最低配置；实施计划可以在同一讲增加第二道练习，但不得减少；新增练习必须可自动判定或按自检清单判定。
- 8 个阶段项目（p0-p7）与毕业项目，全部围绕 LinkHub 主线累积；
- 全站可搜索、可记录进度、可浏览器内运行 Node/Python/SQL 练习；
- 全量审计 0 错误、0 控制台异常，私有发布成功。

### 1.2 重建策略

**保留引擎，重建内容。**

| 对象 | 决策 | 原因 |
| --- | --- | --- |
| `web/index.html`、`web/styles/` | 保留，做少量文案与布局适配 | 视觉与响应式已经可用 |
| `web/scripts/app.js`、`views/`、`engine/`、`store.js`、`lang.js` | 保留，做 8 阶段、附录、草稿态、进度迁移适配 | 判题与路由能力可复用 |
| `web/scripts/content/**` | 全部重建 | 旧内容与 45 讲目录不一致，逐讲打补丁会留下重复与断裂 |
| `python-blocks.js`、`python-tracks.js` | 拆分为按阶段维护 | 45 讲集中在一个文件不可维护 |
| `graduation.js` | 重写为 11 个里程碑 | 旧版偏功能，缺 AI、质量门槛与故障演练 |
| `functions/` | 不动 | 与课程内容无关；`DEMO_SECRET` 维持演示值 |
| 发布 | 全部完成并通过 G8 后一次性私有发布 | 不发布半成品；站点始终私有 |

### 1.3 不做的事

- 不引入构建工具、框架、数据库或付费 API；
- 不为课程新增后端服务；练习继续在浏览器沙箱内运行；
- 不改站点访问范围为公开；
- 不在实施中途发布；
- 不为旧内容做兼容层；旧内容只做一次备份，之后不再维护；
- 不新增课程大纲之外的课时；需要增删课时先改 `docs/curriculum-plan.md` 与本文件的清单。

### 2.1 依赖图

```text
M0 ──> M1 ──> M2 ──> M3 ──> M4 ──> M5 ──> M6 ──> M8 ──> M9
                    │       │       │       │

                    │       │       └──────────> M7(a9-a12)
                    │       └──────────────────> M7(a7-a8)
                    └──────────────────────────> M7(a1-a6)
M7(a10,a12) ──────────────────────────────────> M8
```

- **关键路径**：M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7(a10/a12) → M8 → M9。
- **可并行的旁路**：M2 完成后可提前写 a1-a6；M4 完成后可写 a7-a8；M5 完成后可写 a9-a12；M6 完成后写 a13。单 Agent 执行时按主线顺序推进，不为了并行牺牲一致性。
- **不允许跳过的依赖**：S6 不能在 S5 前写，S7 不能在 S6 前写，毕业项目不能在 S7 与 a10/a12 前定稿，M9 不能在任何模块未过门时开始。

### 2.2 为什么按这个顺序

1. 先修引擎与契约，避免边写内容边改数据结构，导致 45 讲返工。
2. 核心阶段严格按学习依赖排序：S0 网络与运行时 → S1 数据 → S2 契约 → S3 韧性 → S4 生产化 → S5 分布式 → S6 全栈 → S7 AI。
3. 每个阶段项目只在上一个项目代码库上增量演进，内容与项目一起写，避免项目说明与课时脱节。
4. 附录依赖核心课的具体讲次，必须在对应核心讲稳定后再写，避免引用不存在的概念。
5. 毕业项目依赖 S7 与 a10/a12 的模板，最后写，确保答辩、ADR、故障演练都有前置训练。

## 3. 统一执行协议

### 3.1 批次大小

- 核心阶段：每个批次 **2 讲**，最多 3 讲；S6/S7 每批 2 讲。
- 附录：每个批次 2-3 讲。
- 每个批次必须先写课时规格，再写正文；规格未通过自检，不写正文。
- 一个批次未通过自动校验，不开始下一批次。

### 3.2 单批次循环

```text
读大纲与本模块 brief
  → 写 2 份课时规格（docs/content-specs/<lesson-id>.md）
  → 规格自检（范围、目标、块大纲、题与小节对齐）
  → 逐讲写内容（一次只写 1 讲）
  → 跑单讲审计 + JS/Python/SQL 测试
  → 浏览器打开该讲，检查渲染、控制台、移动端
  → 记录证据到 docs/reviews/<module>/<batch>.md
  → 本批 2 讲都通过后，再进下一批
```

### 3.3 硬规则

1. **一讲一文件**：每讲只编辑自己的 `stages/<stage>/<lesson-id>.js` 与对应 `python.js` 中的条目；不跨讲改内容。
2. **先规格后正文**：没有 `docs/content-specs/<lesson-id>.md` 的讲，不允许写正文。
3. **测试先于文案**：代码题的测试用例先定，再写讲解；讲解必须能解释测试里的边界。
4. **不复制粘贴旧段落**：旧内容只作参考，不允许整段搬移；相似度检查超过阈值即失败。
5. **事实先登记**：版本、价格、默认行为、性能数字先写进 `docs/facts/registry.md`，再写进正文。
6. **失败即停**：任何审计错误、测试失败、控制台异常，先修当前讲，不继续下一讲。
7. **不发布**：M9 之前不调用发布操作；站点保持私有。

### 3.4 任务卡格式

每个模块文档中的任务都用统一卡片，模板见 `templates/batch-task.md`：

```text
### T-<module>.<batch>.<n> <动作>
- 类型：engine / spec / content / validation / review
- 依赖：前置任务 ID
- 输入：大纲章节、brief、已有文件
- 产出：精确文件路径
- 约束：本任务不允许改动的文件与范围
- 验收：命令 + 预期输出 + 浏览器检查点
- 证据：写入哪个 review 文件
- 回滚：恢复哪个备份目录
```

1. `node tools/audit-content.mjs`：0 错误；警告逐条解释。
2. `node tools/run-js-exercises.mjs`：0 失败；starter 必须至少失败 1 条。
3. `node tools/run-python-exercises.mjs`：0 失败。
4. `node tools/run-sql-exercises.mjs`：0 失败。
5. `node tools/check-links.mjs`：0 断链。
6. `node tools/check-duplication.mjs`：无超过阈值的段落对。
7. `node tools/check-facts.mjs`：所有版本/数字声明已登记。
8. 浏览器打开本模块全部课时 + 项目页：0 控制台错误，0 未渲染块，移动端无横向滚动。
9. 内容评审按 10 维评分表执行，单讲 ≥18/20，且无 0 分项。
10. 评审报告写入 `docs/reviews/`，包含命令输出摘要、问题与修复、残余风险、门禁结论。

### 4.2 内容评审 10 维评分表

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 范围纪律 | 讲了相邻讲的内容 | 有一处越界 | 只讲本讲一层 |
| 问题先行 | 直接堆概念 | 有场景但不够具体 | 从真实问题切入，读者知道为什么学 |
| 前端类比 | 无 | 有但牵强 | 类比准确且能迁移到后端约束 |
| 事实准确 | 有错误或未标注 | 基本正确但缺来源 | 有来源/版本，无法确认的写清边界 |
| 最小实现 | 无可运行代码 | 代码不完整 | 可运行、可验证、注释解释关键点 |
| 坑与边界 | 无 | 只列现象 | 现象、原因、发现方式、修复与预防 |
| 练习对齐 | 题与目标无关 | 部分对齐 | 每题对应一个 objective，测试覆盖边界 |
| Python 等价 | 无或只翻译语法 | 有实现但差异没讲 | 有实现且讲清运行时差异 |
| 深度 | 只有名词 | 有机制但缺取舍 | 有取舍、失败模式、面试延伸 |
| 结构与可读性 | 大段文字墙 | 块类型单一 | 类比/流程/表/代码/坑/深挖搭配合理 |

S6 加一条「是否跨层」；S7 加一条「是否有评估、成本、安全边界」；AI Coding 加一条「是否可验证、可复盘」。附加项不过，整讲不通过。

## 5. 文件布局

### 5.1 内容

```text
web/scripts/content/
  index.js                     # 只做注册、合并 Python 映射、导出查询函数
  stages/
    s0/
      index.js                 # 阶段元数据 + lessons 数组 + project
      s0-l1.js
      s0-l2.js
      s0-cli.js
      project.js
      python.js                # 本阶段的 PYTHON_BLOCKS / PYTHON_TRACKS
    s1/ … s7/                  # 同样结构
    appendix/
      index.js
      a1.js … a13.js
      python.js
  graduation.js
```

规则：

- 课时文件只导出该讲对象，不写副作用代码。
- 阶段 `index.js` 只做组装与元数据，不写正文。
- 项目独立 `project.js`，便于单独 review。
- Python 映射按阶段拆，键仍是课时/题 ID；内容索引统一合并。
- 不使用 `s6-l1` 这类旧附录 ID；附录统一 `a1..a13`。

### 5.2 文档与工具

```text
docs/
  curriculum-plan.md           # 目录唯一依据，不改
  content-manifest.json        # 45 讲/项目/时长的机器可读清单
  content-specs/               # 45 份课时规格
  facts/registry.md            # 事实登记
  implementation/              # 本目录
  reviews/                     # 每道门的证据
tools/
  audit-content.mjs
```

> 版本控制：源码托管于私有仓库 `advanced-fullstack-web-tutorial`（GitHub）；发布版本用标签标记，不再使用本地 `backups/` 目录。

### 5.3 环境与命令

- Node.js 22+；Python 3.11+（本地校验用，站点运行时仍是 Pyodide 3.13）。
- 本地预览：`python dev_server.py`，默认端口以脚本输出为准。
- 所有工具必须零第三方依赖，只用 Node 标准库与 Python 标准库。
- 不在仓库写入任何密钥；AI 练习只用 mock provider。

## 6. 内容清单与进度迁移

### 6.1 清单

`docs/content-manifest.json` 固定记录：

- 8 个核心阶段与附录的 ID、序号、标题、时长；
- 45 讲的 ID、标题、时长、所属阶段；
- 8 个阶段项目的 ID 与里程碑数；
- 毕业项目的 ID 与 11 个里程碑；
- 总计：45 讲、核心 2510 min、附录 890 min、3400 min。

审计工具逐项比对内容与清单；任何 ID、时长、顺序变化都必须先改大纲与清单。

### 6.2 旧进度迁移

站点进度键仍用 `bff-lab-progress-v1`，读取时做一次性迁移：

- `s6-l1..s6-l6` → `a1..a6`；
- 题目 ID `s6-l1-c1` → `a1-c1`、`s6-l1-e1` → `a1-e1`，含 `@py` 后缀；
- 草稿键 `s6-l1` 与 `s6-l1-e1` 同步映射；
- `meta.version` 升到 2，迁移只执行一次；
- 旧内容中已不存在的课时/题目保留在存储里但不参与统计，不清空用户数据。

验收：构造一份含旧 `s6-l*` 记录的 localStorage 夹具，迁移后报告页能正确识别 a1-a6 的完成状态。

## 7. 版本控制与回滚

源码已纳入 git（私有仓库 `advanced-fullstack-web-tutorial`），git 是唯一回滚手段；本地 `backups/` 已移除，`.gitignore` 保留该目录名防止再次堆积。

1. 每个门禁或发布通过后在 `main` 打标签（如 `v2.0.1`）并推送，发布版本可由标签重建。
2. 单个批次失败：`git restore` 当前课时文件与对应 `python.js` 条目，不回滚整个模块。
3. 模块级失败：回退到最近一次通过门禁的提交，保留评审报告作为问题记录。
4. 发布失败：保留已发布的上一版本；不删除站点、不改访问范围。
5. 每次提交前跑门禁脚本，提交信息写明对应模块或门禁。

## 8. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 内容量大导致失控 | 一次写太多，错误累积 | 每批 2 讲；失败即停；每讲单独审计 |
| 旧内容残留 | 段落重复、概念冲突 | 全量重建；相似度检查；旧内容只做参考 |
| 事实漂移 | 版本/价格/默认行为过时 | 事实登记；版本标注日期；AI 内容只写机制与可替换接口 |
| Python 轨道漂移 | 只翻译语法、运行时差异没讲 | 每讲规格必须写 Python 差异；本地 Python + Pyodide 双跑 |
| 引擎回归 | 8 阶段/附录导致导航、报告异常 | M0 先改引擎并做基线回归；每模块后跑浏览器检查 |
| 进度丢失 | 旧 `s6-l*` 记录失效 | 一次性迁移 + 夹具测试 |
| 提前发布 | 半成品上线 | M9 前禁止发布；保持私有 |
| AI 练习成本/密钥 | 需要付费 key 或泄漏 | 只用 mock provider；密钥只走环境变量；不写仓库 |
