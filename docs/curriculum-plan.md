> 本文件是课程目录的**唯一事实源**。v3 起采用「主修大块 + 选修 + 工具箱 + 可选集成毕业」，不再要求一条 S0→S7 主线学完。
> 目录未定稿的部分，不进入内容生产与 ID 迁移。

## 文档职责与冲突裁决

- **本文件**：大块/章节/课时 ID、标题、时长、先修、路径、项目归属、出口标准、质量门槛、旧 ID 对照。
- **`docs/implementation/*`**：批次、任务卡、工具链与评审门；不得改写本文件的目录级字段。
- **`docs/content-schema.md` / `docs/content-style.md`**：数据形态与写作规范；块类型与题型规则仍适用。
- **冲突**：目录级以本文件为准；执行细节以实施文档为准。变更目录时：先改本文件 → 清单/内容/进度迁移 → 审计。

## 1. 课程定位

| 项目 | 定义 |
| --- | --- |
| 目标学员 | 有 1–3 年前端经验，熟悉 JS/TS、浏览器与 HTTP，希望补齐后端并成长为 AI 时代能独立负责产品线的资深全栈 |
| 结业能力（完整画像） | 数据 → API → 产品层 → 部署/观测/故障；模型能力可评估、可控成本、可防注入；AI Coding 可验证可度量；能写方案讲清取舍 |
| 学习方式 | **路径组合**，不是一本教材从头背到尾；允许阶段结业 |
| 语言轨道 | Node.js 主轨 + Python 对照轨 |
| 教学形式 | 讲解 → 可验证练习 → 块内项目 →（可选）集成毕业 |
| 内容规模 | 仍约 45 讲 / 3400 min；重组为 4 主修 + 1 选修 + 工具箱 + 可选 X |
| 不做什么 | 不训练模型、不教深度学习数学、不做提示词大全；不教前端框架语法与 UI 库；不把 K8s/微服务当「高级」同义词；不绑定单一模型商 |

## 3. 学习路径（产品叙事）

| 路径 | 顺序 | 适合谁 | 阶段结业证明 |
| --- | --- | --- | --- |
| **A 后端补齐** | M1 → M2 → M3 章1 | 前端要独立写 API 并上线 | M2 项目 + M3 章1 项目 |
| **B 全栈交付** | M1 → M2 → M3 全文 | 要端到端产品感 | A + M3 章2 项目 |
| **C AI 全栈** | M1 → **M4-Coding** → M2 → M3 → M4-Product | 主目标（AI 时代资深全栈） | B + M4 两章门槛 |
| **D 资深加深** | B 或 C → E1 → B-Design → X | 架构/面试/带线 | E1 项目 + ADR + LinkHub 答辩 |

规则：

1. 路径是推荐组合，不是门锁；跳块时用入口检查（概念自测）提示风险，不禁止进入。
2. **只有选 X 的人**才强制走长链集成；其余路径允许阶段结业。
3. M4-Coding 默认插在 M1 之后（路径 C）；已会用 AI 的学员可速通，只交协作记录模板。

## 4. 分块目录

ID 规则：`{block}-{slug}`。块 = `m1|m2|m3|m4|e1|b|x`。项目 ID：`p-{block}-{slug}`。

### 4.1 M1 地基（3 讲 / 170 min）

**目标**：看见请求全路径，理解运行时为何被阻塞，掌握排障基本功。

| 新 ID | 标题 | 时长 | 旧 ID | 练习 |
| --- | --- | --- | --- | --- |
| `m1-http` | 从 URL 到响应：请求的四段旅程 | 55 | `s0-l1` | 检查 + 代码：分段计时 |
| `m1-runtime` | Node.js/Python 运行时：事件循环与并发模型 | 60 | `s0-l2` | 检查 + 代码：输出顺序 |
| `m1-cli` | 命令行与排障：进程、端口、日志与 curl | 55 | `s0-cli` | 检查 + 代码：排障脚本 |

**项目 `p-m1-probe`**（旧 p0）：HTTP 探针 CLI；任一段耗时异常时能定位到段。

**出口**：能口述慢请求排查顺序；能解释同步阻塞；能用 CLI 定位端口/进程/DNS。

### 4.2 M2 后端交付（8 讲 / 620 min）

**目标**：从对象到可信任数据，再交出让第三方敢依赖的 API。  
**块内顺序**：先数据章，后 API 章。

#### 章 · 数据

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m2-sql` | 关系模型与 SQL：从对象到表 | 80 | `s1-l1` |
| `m2-index` | 索引与查询计划 | 85 | `s1-l2` |
| `m2-tx` | 事务、隔离级别与 MVCC | 80 | `s1-l3` |
| `m2-schema` | 数据建模、约束与迁移 | 75 | `s1-schema` |

#### 章 · API

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m2-resource` | 资源建模与 HTTP 语义 | 75 | `s2-l1` |
| `m2-errors` | 输入校验与错误契约 | 75 | `s2-l2` |
| `m2-auth` | 认证、授权与多租户 | 75 | `s2-l3` |
| `m2-contract` | 对外 API 的工程化 | 75 | `s2-l4` |

**边界**：`m2-contract` 只讲对外契约与语义（分页/幂等键契约/429 语义/OpenAPI）；限流算法实现在 `m3-ratelimit`。

**项目**：

- `p-m2-data`（旧 p1）：用户/资源表、索引、迁移、并发约束——**本块自洽**，不强制后续统计服务。
- `p-m2-api`（旧 p2）：在 `p-m2-data` 上加 REST/JWT/错误信封/OpenAPI/契约测试。

示例域默认短链（LinkHub 数据形状可复用），但验收以「本块出口」为准，不要求接 p5/p6。

**出口**：能建模并证明索引；能交付可契约测试的 API。

### 4.3 M3 生产与产品（12 讲 / 980 min）

**目标**：服务在压力下行为可证明；能力能组装成用户可见产品。  
**块内顺序**：章1 生产 → 章2 产品（路径 A 可只完成章1）。

#### 章1 · 生产（8 讲 / 650 min）

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m3-cache` | 缓存分层与失效策略 | 85 | `s3-l1` |
| `m3-queue` | 消息队列与异步任务 | 85 | `s3-l2` |
| `m3-ratelimit` | 限流、配额与过载保护 | 85 | `s3-l3` |
| `m3-resilience` | 超时、重试、熔断与幂等 | 85 | `s3-resilience` |
| `m3-otel` | 日志、指标与追踪 | 80 | `s4-l1` |
| `m3-perf` | 性能压测与瓶颈定位 | 75 | `s4-perf` |
| `m3-container` | 进程、容器与配置 | 80 | `s4-l3` |
| `m3-cicd` | CI/CD 与发布策略 | 75 | `s4-l4` |

**项目 `p-m3-ship`**（合并旧 p3+p4 验收，实现可分两里程碑）：

1. 缓存 + 异步 + 限流/幂等；压测对比报告。  
2. 结构化日志/指标、容器、流水线、一次灰度与回滚。  
可选加分：真机/VPS（Nginx+TLS）部署档，不阻挡站内结业。

**章1 出口**：能证明保护与观测生效；能发布并回滚。  
**章1 末方案题**：写清「何时不该拆成独立服务」（为 E1 留判断力，不强制实现）。

#### 章2 · 产品（4 讲 / 330 min）

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m3-bff` | 契约驱动的全栈开发与 BFF | 85 | `s6-l1` |
| `m3-render` | 渲染架构与端到端性能 | 85 | `s6-l2` |
| `m3-realtime` | 实时、认证与全栈安全 | 80 | `s6-l3` |
| `m3-edge` | 边缘部署、特性开关与全栈可观测性 | 80 | `s6-l4` |

**边界**：不讲框架语法；不重复 Redis 缓存课与后端 OTel 课，只补产品层、边缘与 RUM。

**项目 `p-m3-web`**（旧 p6）：类型客户端、BFF 聚合、SSR/流式预算、会话安全、实时看板、特性开关、RUM↔trace。后端复用 M2/M3 章1 能力，不重写业务服务。

**章2 出口**：契约→UI→观测闭环；CWV/安全头/键盘可达达门槛。

**跨层验证（M3 章2 最低）**：契约→UI；传输→UI 状态；浏览器→服务端 trace。

### 4.4 M4 AI 工程（5 讲 / 400 min）

**目标**：把 AI 协作变成工程系统；把模型接进产品且可评估、可控成本、可防注入。  
**两章先修解耦**：Coding 可早学；Product 在 M2 之后。

#### 章 · Coding（可早学，2 讲 / 155 min）

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m4-coding-system` | AI Coding 的系统模型：任务、上下文与验证 | 80 | `s7-l4` |
| `m4-coding-team` | Agent 工作流、工具链与团队落地 | 75 | `s7-l5` |

**教学骨架（保留）**：任务/上下文/执行/验证/系统五层；七步循环；任务分类矩阵；失败 taxonomy；成熟度 M1–M5；禁用虚荣指标。

**练习**：协作任务夹具 + 独立验证 + 协作记录；不要求付费密钥。

#### 章 · Product（3 讲 / 245 min）

| 新 ID | 标题 | 时长 | 旧 ID |
| --- | --- | --- | --- |
| `m4-llm` | LLM 应用基础与流式网关 | 80 | `s7-l1` |
| `m4-rag` | RAG、向量检索与工具调用 | 85 | `s7-l2` |
| `m4-eval` | AI 功能评估、安全与成本 | 80 | `s7-l3` |

**项目 `p-m4-ai`**（旧 p7）：摘要/标签、语义搜索、受限问数、SSE、评估进 CI、注入用例、成本与降级、协作记录。默认 mock provider。

**出口**：能设计可上线 AI 功能；能判断何时不用模型；能用证据验收 AI Coding 产出。

### 4.7 X 集成毕业（可选 · 项目制）

**目标**：把已学多块收成可部署、可运营、可答辩的产品线。默认产品：LinkHub。

| 里程碑 | 交付 | 依赖块 | 验收要点 |
| --- | --- | --- | --- |
| X1 契约与认证 | OpenAPI、JWT/RBAC | M2 | 契约测试；越权 403 |
| X2 核心链路 | 创建/跳转/管理 | M2 | 跳转 P99；410 语义 |
| X3 缓存与保护 | Redis、限流、幂等 | M3 章1 | 热点不击穿；429 |
| X4 异步统计 | 统计链路 | M3 章1 或 E1 | 重复只计一次；可降级 |
| X5 可观测与交付 | OTel、Docker、灰度回滚 | M3 章1 | requestId 还原；真实回滚 |
| X6 Web 与 BFF | 类型客户端、SSR、实时、会话 | M3 章2 | 漂移/CWV/重连 |
| X7 质量门槛 | CWV、CSP、RUM、a11y | M3 章2 | 四项全过 |
| X8 多租户后台 | 管理与隔离 | M2/M3 | 跨租户拒绝 |
| X9 AI（可选档） | 摘要/搜索/问数/评估 | M4-Product | 五项 AI 门槛 |
| X10 答辩 | ADR、容量、故障、AI 协作复盘 | B + 路径 | 三个取舍、两个失败模式、一次恢复 |

**结业档**：

- **全栈档**：X1–X8 + X10（路径 B 毕业生）。  
- **AI 全栈档**：全栈档 + X9（路径 C）。  
- **分布式档**：X4 必须用 E1 的 Outbox/独立消费者方案（路径 D）。
