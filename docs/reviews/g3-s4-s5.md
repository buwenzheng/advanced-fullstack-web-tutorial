### 6.3 练习抽题

在真实页面 UI 中切换语言标签、展开「查看参考答案」、把参考实现填入编辑器并点击「运行测试」：

| 课时 | 练习 | Node 轨道 | Python 轨道 |
| --- | --- | --- | --- |
| s5-l3 | `createFencedLock` 租约锁 | 7/7 通过，状态「已通过」 | 7/7 通过 |
| s5-data-scale | `createHashRing` 一致性哈希环 | 7/7 通过 | 7/7 通过，Pyodide 显示「Python 3.13 · 浏览器内执行」 |

**本轮发现与修复**：s5-data-scale 第一次在浏览器 Node 轨道运行时只有 6/7，失败项为「删除节点只迁移该节点的 key」，错误是 `assert.notEqual is not a function`。根因是浏览器 worker 的 `assert` 只实现 `equal / deepEqual / deepStrictEqual / strictEqual / throws / rejects / ok`，而 CLI 使用 Node 原生 `assert`，多出 `notEqual`，导致 CLI 全绿掩盖了浏览器不兼容。处理分两层：

1. 内容层把该断言改为文档允许的 `assert.ok(after.getNode(key) !== 'node-3', ...)`。
2. 工具层在 `tools/audit-content.mjs` 增加浏览器断言白名单，任何测试使用白名单外的方法都会在审计阶段报错，避免再次出现「CLI 通过、浏览器失败」。

修复后 `audit --drafts` 仍为 0 错误，JS 22/22 全过，浏览器内 s5-data-scale Node 与 Python 轨道均 7/7 通过。

## 8. 残余风险

- 教学实现与生产实现的差距已在正文 note 声明：内存 store 只模拟 `SKIP LOCKED` 的抢占互斥，不模拟进程崩溃后锁随事务释放；租约测试使用注入时钟；真实实现依赖数据库事务、唯一索引与 broker 语义。课程只讲机制，不承诺代码可直接上线。
- CLI 与浏览器判题器仍有细节差异：CLI 使用 Node 原生 `assert` 的深比较语义，浏览器 worker 使用自定义结构比较。本次已用审计白名单消除方法名差异，但两端深比较的极端边界（如带原型的对象）仍可能不同；课程测试统一使用普通数据，避免依赖差异行为。
- Python 展示代码块不进入 `run-python-exercises`，只做语法编译与审阅；每讲 Python 轨的 7/8 条测试覆盖练习路径。浏览器首次运行 Python 需要下载约 10 MB Pyodide 运行时，首次等待时间取决于网络。
- p4/p5 的可执行产物（压测报告、回滚记录、Outbox 发布器、消费者、故障演练）不在仓库内，属于学员任务；G3 只保证文案可执行且口径一致。
- s5-data-scale 的均衡份额依赖固定 key 夹具；若未来替换默认哈希、虚拟节点数或节点名，需要同步重算断言。测试已写明 10%–30% 的意图，避免变成魔法数字。
- 22 讲 draft（S6 4、S7 5、附录 13）按计划保留；ready 模式审计与最终内容统计要在 G8 发布前重新执行。
