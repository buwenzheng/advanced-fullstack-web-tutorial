## 3. 本轮发现与修复

1. `tools/run-python-exercises.mjs` 的 `indent()` 把测试代码中的空行替换为 `pass` 并在 4 空格处注释，导致多行 `class` 定义被提前截断，s4-l3 的 7 条测试全部缩进报错。已改为保留空行、仅当整个测试为空时才补 `pass`；Python 空行本身合法，这是根因修复而不是内容绕行。
2. `web/scripts/engine/exercise.js` 的 Python harness 只对 `test.async` 使用 `async def`，而 s4-l3 的测试需要 `await`。现已统一生成 `async def`，运行时本就通过 `inspect.isawaitable` 兼容同步与异步函数；S0-S3 的同步测试不受影响。
3. Python 优雅退出协调器初版把 `state='draining'` 与 `server.close()` 放在协程内，`shutdown()` 返回后到事件循环调度前存在窗口，测试观察到状态仍为 `running`、close 回调丢失。现改为 `shutdown()` 内同步置状态并注册 close 回调，再调度等待任务，与 JS 版的同步语义一致。
4. `_wait()` 在正常排空分支漏写 `return self._finalize(...)`，导致结果为 `None`、状态停在 `draining`；已补上返回，7 条 Python 测试全部通过。
5. starter 均保持故意错误：s4-l3 直接 `server.close()` 并立即返回成功、永不进入 draining；s4-l4 用数字 userId 取模、忽略 kill switch/白名单/黑名单。18 道 Python starter 全部失败，练习有区分度。
6. s4-l4 的 FNV-1a 在 JS 侧用 `Math.imul` 后 `>>> 0`，Python 侧用 `& 0xFFFFFFFF`；两端的拼接格式统一为 `flag.key + ':' + userId`，保证同一用户跨语言落同一桶。

## 4. 边界与对齐检查

- `s4-l3` 只讲进程信号、优雅退出、镜像构建、探针与配置；cgroups 只解释内存上限与 CPU 节流对进程行为的影响，Linux IO 与反向代理留给 a8。
- `s4-l4` 只讲流水线关卡、发布策略、expand-contract 与特性开关；测试策略与工程效能留给 a11，正文明确「两小时全量 E2E 不进合并门禁」。
- `p4` 的 5 个里程碑与四讲一一对齐：可观测性（s4-l1）、压测与瓶颈（s4-perf）、容器化（s4-l3）、CI/CD 与灰度回滚（s4-l4）。
- Python 轨与 Node 题测试数量一致（各 7 条）；Node 的 `RangeError` 等错误类型在 Python 侧按习惯映射为 `ValueError`。
- 优雅退出测试使用注入的 scheduler 与手动推进，不依赖真实计时；Python 超时用 `timeout_ms=0` 立即触发，避免不稳定。
