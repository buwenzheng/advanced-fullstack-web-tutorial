## 3. 代码题

### s7-l3 评估门槛 + 工具授权

11 条测试：

1. 固定评估集全部通过：24 条用例、四项指标均为 1、failures 为空，并断言用例数为 24。
2. 缺少引用判失败并记录 `MISSING_CITATION`。
3. 应拒答却回答判失败（`SHOULD_REFUSE`）；不应拒答却拒答同样判失败（`UNEXPECTED_REFUSAL`）。
4. 注入用例调用禁止工具判失败（`DISALLOWED_TOOL`）。
5. 阈值使用大于等于且空分母记 1：引用、拒答、注入三类用例缺失时不虚增失败。
6. 空评估集判失败并给出 `EMPTY_EVALUATION`，防止「没跑就算过」。
7. 正常工具调用放行。
8. 未知工具拒绝（`UNKNOWN_TOOL`）。
9. 跨租户拒绝（`TENANT_MISMATCH`）。
10. 超过行数上限拒绝（`LIMIT_EXCEEDED`）。
11. 任意 SQL 字段拒绝且不抛异常（`ARBITRARY_FIELD`）。

授权顺序固定为：工具白名单 → 租户 → 字段白名单 → 行数 → 时间范围 → 指标。`authorizeToolCall` 只返回 `{ allowed, reason }`，不抛异常，理由码可直接进日志与告警。

### s7-l4 AI 变更验证门

13 条测试：正常变更通过、删除测试阻断、跳过测试 warn、测试失败阻断、新增依赖阻断、禁止路径阻断且不重复报越界、越界路径阻断、密钥模式阻断、文件数超限 warn、diff 行数超限 warn、findings 按严重度与 code 排序、空变更 warn 而未运行测试阻断、行为变更缺少测试变更 warn。

判定口径：`block` 项任一存在即 `block`，否则有 `warn` 即 `warn`，都没有才 `pass`；排序先按严重度（block 在前）再按 code 字典序，保证报告可复现。

## 5. 注入用例结果

`injection-corpus.js` 共 14 条：user 8、webpage 1、document 2、tool-output 1、email 1、log 1；其中 8 条带工具调用企图，6 条为纯文本行为用例。8 条工具企图全部被拒绝，理由与预期一致：

## 9. 边界自查

- s7-l3 未重复 s6-l3 的 Web 安全：全文无 CSRF、CSP、Cookie 属性与 OIDC 流程；只讲 AI 功能的评估、注入与成本。
- s7-l3 未展开模型训练与微调；成本只讲 token 计量、预算与降级。
- s7-l4 未写提示词大全与模型原理：只讲任务分类、最小充分上下文、验证独立性与控制回路。
- s7-l4 未评测具体 AI 工具：只用变更场景与验证门，不比较厂商。
- 两讲均未出现推理服务、KV cache、量化或 GPU 集群运维。

## 10. 残余风险

- 评估集为固定 24 条，覆盖六类但规模有限；真实项目需按线上失败样本扩充，正文与方案题都要求版本化与持续回归。
- 注入语料的 6 条纯文本用例依赖模型行为，测试以评估集的拒答与引用判定间接覆盖，无法在纯函数层直接断言「模型没被说服」。
- AI 变更验证门基于变更元数据（文件、测试计数、diff 文本），不解析 AST；正文限定它用于准入而不是替代人工 review。
- 成本场景只验证预算与降级决策，不接入真实计费；金额以整数分表示，避免浮点误差。
