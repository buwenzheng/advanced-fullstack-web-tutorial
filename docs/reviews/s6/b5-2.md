## 3. 代码题

### s6-l3 重连计划 + 实时事件归并（跨层）

- 9 条测试：退避序列、封顶、jitter 上下界、耗尽、重复只累加一次、两个链接独立、乱序按 id 去重、seq 缺口三态、入参不可变。
- 跨层证据：`applyLiveEvent` 的输入是传输层事件 `{ id, linkId, delta, seq }`，输出直接是 UI 状态；测试覆盖重复（同 id 忽略）、乱序（seq2 先到、seq1 后到）与缺口（seq4 跳号后 gap 粘性为 true）三种真实传输状态。
- 入参不可变：测试先序列化快照，调用后逐字段比对原对象未变。

### s6-l4 边缘缓存 + trace 合并（跨层）

- 9 条测试：fresh 命中、SWR 旧值 + 后台刷新、同 key 单飞、超过 SWR 回源 miss、bypass、刷新失败保留旧值且可重试、trace 正常合并、trace 缺失/不匹配 incomplete、span 乱序排序。
- 跨层证据：`joinTrace` 以浏览器 LCP 为终点合并服务端 span，7 号用例得到 `totalMs=4200` 与 `largestGap=3000`（结尾渲染等待），8 号用例对 traceId 缺失/不匹配返回 `incomplete: true` 而不是伪完整链路。
- 单飞证据：两次 stale 请求后后台刷新只调用一次 `load`；失败后再次 stale 可重新触发，成功后缓存更新。

## 7. 残余风险

- `whenIdle()` 只等待后台刷新，不等待 miss 请求；miss 本身由调用方 await，语义已限定。
- `joinTrace` 以按开始时间排序后的最后一个 span 作为结尾基准；嵌套 span 场景需要调用方先扁平化，正文已暗示服务端 span 应为请求主链路。
- Python 的 `create_task` 需要事件循环调度，测试用 Future 与 `when_idle` 消除时序不确定性。
