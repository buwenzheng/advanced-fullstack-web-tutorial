### 2.1 里程碑可检查性

- **p6-m1**：要求「重新生成后与仓库不一致即失败」，并给出删字段/改类型的失败样例，漂移检查有明确命令与判定。
- **p6-m2**：明确「总超时小于各上游超时之和」、`degraded` 标记与 `NOT_FOUND` / `UPSTREAM` 错误码映射测试，对应 s6-l1 的 `loadDetail` 契约。
- **p6-m3**：给出具体数字 LCP ≤ 2500ms、INP ≤ 200ms、CLS ≤ 0.1，采用 p75 最近秩口径，连续两个观察窗未达标阻止发布。
- **p6-m4**：逐项可检查：Cookie 属性、localStorage 无 token、CSRF 缺失时写操作被拒、越权 403、CORS 不通配 credentials。
- **p6-m5**：断网自动重连并补拉、重复不重复计数、seq 缺口有标记、降级轮询可恢复，对应 s6-l3 的三态归并。
- **p6-m6**：双账号同 URL 不串号、kill switch 分钟级回滚、RUM 与服务端 trace 同一 traceId 合并且缺失标 incomplete，对应 s6-l4 的 `joinTrace`。

### 2.2 与 p2-p5 的边界

- 第 1 步直接从 p2 的 OpenAPI 生成客户端，不重写 API；第 2 步复用 p5 的统计摘要，第 5 步复用 p3 的异步点击数据；边缘缓存只加在 Web 层。
- 清单第一条即「只加产品层，不重写 p2-p5 的接口、缓存、队列与统计」，第二条「统计与点击数据复用 p5，不新建第二套统计服务」。
