## 3. 代码题

### s6-l1 类型客户端 + BFF 聚合

- 9 条测试：路径/查询编码与排序、未知路径、缺失路径参数、响应必填校验、三上游并发启动、全成功形状、stats 降级、meta 错误码映射、总超时与迟到结果忽略 + meta 未完成 UPSTREAM。
- 并发证据：测试在 `loadDetail` 返回后立即断言三个上游均已启动，顺序实现无法通过。
- 降级证据：`degraded` 精确等于 `['stats']`，且 stats 为 `null`、其余字段保留。
- 超时证据：注入假 scheduler 推进到 `timeoutMs`；迟到结果 resolve 后再次断言 `result.stats` 仍为 `null`。

### s6-l2 渲染策略 + 性能预算

- 8 条测试：SSG、流式、CSR、SSR 与缺省、全部达标、最近秩与边界、NO_DATA、多违规排序。
- p75 采用最近秩；等于预算时通过，避免「差一点也算超标」。

## 7. 残余风险

- Python 的 `wait_for` 会取消超时任务，与 JS「忽略迟到结果」语义略有差异；两者对返回结果一致，正文已说明按结果验收。
- s6-l1 的 `transport` 为注入函数，未演示真实 HTTP 客户端；这是刻意保持可测试，方案题要求学员给出真实接入方式。
