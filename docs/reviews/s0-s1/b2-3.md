## 5. 问题与修复

1. **迷你 SQL 引擎不支持 JOIN / GROUP BY / 聚合。** 扩展了词法关键字、`FROM` 多表与 `LEFT/INNER JOIN ... ON`、限定列名、`GROUP BY`、`HAVING`（按 SELECT 别名）、`COUNT/SUM/MIN/MAX/AVG`、`COUNT(DISTINCT ...)`、分组投影与排序。用 s1-l1 的时间窗口查询和 s1-l2 的分页查询做回归，`run-sql-exercises` 2/2 通过。
2. **计划中的 top-3 per user 需要窗口函数，迷你引擎不支持。** 可执行 SQL 题调整为「窗口内每个链接的点击数」，覆盖 LEFT JOIN、时间边界、0 点击与 NULL；正文用只读 PostgreSQL 对照展示 `ROW_NUMBER()` 方案。该偏差已写入 s1-l1 规格与本节报告，G1 不声称 top-3 已被自动测试覆盖。
3. **浏览器判题器缺少 `assert.deepStrictEqual` / `assert.throws` / `assert.rejects`。** CLI 判题器使用 Node `assert`，页面内 worker 只有自定义 `assert.equal`，导致课时在浏览器里出现「deepStrictEqual is not a function」。已在 `web/scripts/engine/runner.js` 补齐别名与异常断言；s1-l2 的 6 条测试在浏览器内复跑全部通过。
4. **s1-l2 SQL 起始查询缺少 `id` 第二排序键。** 起始查询在并列时间上按输入顺序返回，与期望的 `id` 降序不同，能形成有效区分；参考解补上 `ORDER BY created_at DESC, id DESC`。
5. **s1-l1 流程块错别字。** 「一對一」改为「一对一」。

## 6. 残余风险

- 迷你 SQL 引擎是教学子集：不支持窗口函数、子查询、`UNION`、`RIGHT/FULL JOIN` 的实际执行；正文已标注能力边界，SQL 题不依赖这些语法。
- `HAVING` 只支持引用 SELECT 别名，不支持在 `HAVING` 中直接写聚合表达式；本批题目未使用 `HAVING`，后续若使用需先扩展引擎或改题。
- EXPLAIN 解析题的 `actualTime` 是节点自身耗时的教学口径，与真实数据库的累计时间语义不同；正文与规格已明确说明。
- PostgreSQL 相关行为只写机制、不绑定版本；真实执行仍需以项目环境的 `EXPLAIN` 输出为准。
- 站点保持私有，未执行任何发布操作。
