## 3. 单讲结果

### s1-l3 事务、隔离级别与 MVCC

- 11 个内容块：analogy（多人协作文档）、text+table（ACID 与四类异常）、table（隔离级别与默认值）、flow（MVCC 快照读与当前读）、code（同事务创建链接与审计）、code（乐观并发更新与重试）、pitfall（长事务拖垮连接池）、steps（复现丢失更新）、compare（乐观/悲观/串行化）、深挖（连接池与 Little's law）、note（面试延伸）。
- 3 道检查：丢失更新的单选取证、隔离级别与 MVCC 默认值的多选、连接池长事务诊断的单选。
- 2 道练习：
  - 代码题 `updateWithRetry(store, id, mutate, { maxRetries })`：6 条测试，覆盖一次成功、冲突后基于最新版本重试、重试耗尽、两个并发更新不丢更新、`mutate` 抛错不写入、记录不存在不写入；Node/Python 双轨，起始代码只尝试一次，必然失败。
  - 方案题 `LinkHub 事务边界`：9 条自评清单，覆盖事务范围、幂等、重试上限、隔离级别选择、长事务、连接池、监控与回滚。
- 关键语义：使用微任务交错让两个并发调用同时读到 version 1，CAS 串行化后失败方重试，最终 count=2、version=3、写入 2 次，确定性复现且不依赖真实延时。

### s1-schema 数据建模、约束与迁移

- 10 个内容块：analogy（TypeScript 类型与数据库约束）、text+table（约束类型）、table（LinkHub 约束清单）、flow（迁移生命周期）、code（FNV-1a 校验和与 `migrateUp`）、steps（expand-contract 六步）、pitfall（破坏性迁移）、compare（框架迁移与原生 SQL）、深挖（锁级别与在线 DDL）、note（面试延伸）。
- 3 道检查：软删除与部分唯一索引、危险迁移多选、expand-contract 顺序。
- 2 道练习：
  - 代码题 `createMigrator({ migrations, store })`：7 条测试，覆盖按版本执行、跳过已应用迁移、校验和不匹配、重复版本、迁移失败回滚并停止、逆序 down、down 失败停止；Node/Python 双轨。
  - 方案题 `零停机新增 tenant_id`：8 条自评清单，覆盖 expand-contract、回填、双写、约束验证、索引并发创建、回滚与观测。
- 迁移器将「执行迁移」与「记录版本」放入同一事务；失败时通过 store 快照回滚，测试断言不会留下半条迁移记录。

## 5. 问题与修复

1. **Python 判题器把嵌套类中的空行改成 `pass`，导致 `s1-l3` 的测试代码出现 `IndentationError`。** 原因是 `tools/run-python-exercises.mjs` 的 `indent()` 会给所有空行补 `pass`，空行位于嵌套 `class Store` / 嵌套函数体内时会提前结束代码块。已移除 Python 测试代码中嵌套类与函数体内的空行；后续 Python 测试遵循「嵌套块内不写空行」的约束。该行为记录为残余风险，未改动判题器以免影响既有题目。
2. **`s1-schema` 首条测试断言取错日志容器。** 测试期望在迁移器外层 `log` 中看到 `record:1..3`，实际假 store 把 `record/remove` 写进自己的 `store.log`。断言已改为 `store.log.filter(...)`，测试通过。
3. **规格初始写了 5 个目标，超出课时目标上限（3-4 个）。** `s1-l3` 将「乐观并发」与「长事务/连接池」合并为第 4 个目标，对齐表同步收敛为 O1-O4；`s1-schema` 保持 4 个目标。
4. **表块渲染不显示 `note` 字段。** 本批内容未依赖表格备注，改用正文或 note 块承载补充说明；未改动 `web/scripts/views/blocks.js`。

## 6. 残余风险

- Python 测试代码不能在内层类/函数体内包含空行；这是判题器缩进实现的教学约束，已在本批规避，后续生产需持续遵守或单独修复判题器。
- 事务与隔离级别结论以机制为主，不绑定具体数据库小版本；MySQL 幻读在 REPEATABLE READ 下的行为随语句类型与版本变化，正文已注明以实测为准。
- `CREATE INDEX CONCURRENTLY`、在线 DDL、部分唯一索引等只做机制与取舍讲解，不声称在本地迷你引擎中执行；迁移题验证的是编排逻辑，不是真实 PostgreSQL 锁行为。
- 迷你 SQL 引擎仍不支持窗口函数、子查询与 UNION；本批未使用这些语法。
- 站点保持私有，未执行任何发布操作。
