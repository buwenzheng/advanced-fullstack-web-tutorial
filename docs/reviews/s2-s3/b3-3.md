## 3. 本轮发现与修复

1. Python 字典无法区分「没有 key」与「缓存了 None」。实现改为先取 entry、再用 `entry is not None` 判断，空值走 `negative_ttl`，避免负缓存被误判为未命中。
2. Python single-flight 若用 `asyncio.Lock` 包住整个 loader，会让第二个请求在锁上等待且无法复用结果；改用 `asyncio.ensure_future` 创建一次 Task，后续并发调用 `await` 同一个 Task，并在 `finally` 清理 inflight。
3. 队列的 `attempt` 如果只在 `nack` 时递增，超时重投不会计数，毒消息会绕过 `maxAttempts`。实现改为在 `reserve` 时递增，超时与 nack 两条路径都能进入死信。
4. `consume` 的 handler 可能是普通函数或协程函数；Python 轨用 `inspect.isawaitable` 兼容，JS 轨统一 `await`，并在测试中覆盖失败不 ack、重复 eventId 只执行一次。
5. 缓存流程块包含浏览器与边缘层，存在越界风险；正文对 CDN 只保留「本讲不展开，s6-l4 负责」的边界说明，没有写边缘失效机制。

## 5. 残余风险

- 缓存实现按插入顺序淘汰，不是 LRU；正文与 note 已声明，生产实现需要换成合适淘汰策略。
- single-flight 只覆盖单实例；多实例仍会各自回源一次，需要靠分布式锁或请求合并进一步收敛，成本与复杂度更高，正文未展开。
- 队列实现是单进程教学模型，`reserve` 的并发原子性没有覆盖；真实队列依赖 broker 的锁与投递语义。
- DLQ 重放工具只在方案题中要求，代码题只提供 `deadLetters()` 读取；p3 项目需要补可执行重放记录。
- 事实登记覆盖了 Redis 过期、AMQP/BullMQ/Kafka 的投递语义，但未写具体版本与默认参数，符合「版本相关结论不写死」的规范。
