## 3. 本轮发现与修复

1. JS 判题沙箱没有 `btoa/atob` 与 `Buffer`，s2-l4 的游标题不能依赖平台 base64。实现改为手写 base64url 字母表编解码，练习 hint 与 note 说明原因；Python 轨用标准库 `base64`，两种语言的实现差异写进 note。
2. Python `base64.urlsafe_b64decode` 默认忽略非法字符，`'***'` 会被解码成空字节。测试同时覆盖 `'***'` 与 `'e30'`（合法编码但结构缺失），solution 在解码后强制校验 `createdAt`/`id` 均为字符串，确保两类坏游标都抛 `InvalidCursorError`。
3. 授权判定初稿容易先判断 owner 再判断租户，导致平台管理员跨租户写被放行。实现与正文统一为「资源存在 → action 合法 → 匿名 → 租户 → owner → admin → 成员」；测试包含「管理员跨租户读允许、跨租户写/删拒绝」。
4. p2 原项目文案只有 5 步、4 个里程碑，与实施计划的 6 步、p2-m1..m5 不一致；已按计划补齐「幂等键与限流响应头」「OpenAPI 漂移检查」与「校验与错误」里程碑。

## 5. 残余风险

- 租户仓储示例绑定 `asyncpg` 风格占位符，换驱动需要调整；note 已说明结构不变、参数化绑定不变。
- webhook 示例使用 Node 的 `node:crypto`，不在浏览器沙箱内运行；正文标明边缘运行时改用 Web Crypto 的 HMAC，机制一致。
- 游标不签名，调用方可以构造合法结构但指向任意记录的游标。当前契约靠「排序键 + 记录必须存在」限制影响面；若未来游标包含敏感过滤条件，需要加签名或改用服务端存储。
- p2 的契约测试与 OpenAPI 漂移检查尚未落地，属于项目任务，需在 G2 项目检查中核对文案完整性。
